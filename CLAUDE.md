# Silico

Silico is a parametric CAD system: a Rust core, an egui/wgpu UI, and OpenCascade as the kernel. It's agent-native, meaning agents and humans are equal clients, and git-native, meaning models are diffable text. It ports FreeCAD's behavior into idiomatic Rust.

**Read [ARCHITECTURE.md](ARCHITECTURE.md) before structural work.** Its invariants are non-negotiable unless the maintainer agrees to change them.

- `silico-worker`: what every worker process is: the inherited socket, the request loop, and logging, shared by every worker; and the floating-point trap checks (`Traps::Checked`), by the workers whose output is a result (kernel, STEP, sketch), not by the render worker (`Traps::Unchecked`, docs/design/m4.6-render.md, R5) (its `unsafe`, for inherited descriptors only, is ARCHITECTURE.md's one exception).
- `silico-render`: the render worker (`silico-render-worker`), which draws the core's scenes headless with Rerun's `re_renderer` on Mesa's lavapipe (pinned in pixi, its paths compiled in), its PNG and ID buffer read back, and the render benchmark. The viewport (M5) grows from it.
- `silico-cli`: the `silico` command: `check` (with `--json` and `--fresh`), `fmt` (with `--check` and `--merge-touching`), `show`, `cache clear`, `export` (3MF or STEP), `schema`, `textconv` for `git diff`, and `serve`, the MCP server, which won't start (exit 2) unless all four workers, the kernel, sketch, render, and STEP workers, are there, naming each one missing and where it looked (docs/cli.md), each a thin client of the core's commands (`silico_core::command`).
- `silico-mcp`: the MCP server `silico serve` runs (docs/design/m4.9-mcp.md): MCP 2025-06-18 over stdio, its JSON-RPC written by hand, with no SDK and no async runtime. Every command is a tool (`tests/contract/tools.json`), its arguments reaching the core as the client's text (`Sessions::call_command`) and its answer the core's envelope, byte for byte; `status`, `cancel`, `read_logs`, `version`, and `schema` are answered at once, taking no slot, and at most 64 other calls run at once; a client's cancellation is `cancel`'s, and a client that goes away has its sessions closed. How to connect an agent, its workflow, and its errors: [docs/mcp.md](docs/mcp.md).
- `silico-app`: the app (docs/design/m5.0-app.md, M5.4): a window drawn by `eframe` on wgpu, one client of the core's command API as MCP's server and the CLI are (invariant 3), never waiting on a command (invariant 4); it starts with all four workers or not at all, warms one kernel and one sketch worker off its UI thread, and lays out Fusion's panes (`egui_tiles`) with Rerun's look (`theme`). Its tests drive it through the accessibility tree (`egui_kittest`) on a UI thread marked so a wait fails them.
- `silico-font`: Inter Medium, the app's one font, with its OFL-1.1 licence, a crate of its own so `deny.toml` admits that licence for it alone.
- `silico-view`: a debug viewer that shows the kernel's parts in Rerun, until the app exists; its library logs any mesh (faces shaded by the kernel's normals, labelled edges) for tests and scripts.
- `silico-oracle`: the FreeCAD oracle harness. Each case in `tests/oracle/` (protected) is built through a kernel worker and through headless FreeCAD and compared: volume, area, and center of mass measured as FreeCAD measures them, the tight bounding box, topology counts, and validity, to a tolerance set by what the shape is made of. Each sketch in `tests/oracle/sketches.silico` is solved through the sketch worker and by FreeCAD's `sketch.solve()`, and compared: degrees of freedom, conflicting and redundant constraints, how each side ends, and the solved geometry. Each pair in `tests/oracle/measures/` is measured by the core's `distance` and `angle` and by FreeCAD's Measure module, and compared, by rule and with values worked by hand.

## FreeCAD reference

- FreeCAD's source is a separate clone at `~/Git/FreeCAD`, outside this repository, with full history. It's the maintainer's fork, kept for reference and for upstream PRs: read it, but don't modify it from Silico work. If it's missing, run `git clone git@github.com:trevin-lee/FreeCAD.git ~/Git/FreeCAD`.
- [docs/freecad-map.md](docs/freecad-map.md) maps each Silico subsystem to FreeCAD's code, and shows how to mine FreeCAD's history and run it headless.
- **Port behavior, not lines.** Before porting a subsystem, write `docs/ports/<subsystem>.md` covering what it does, its edge cases, the bug fixes from FreeCAD's git history (with commit hashes), and which FreeCAD tests to port. Then implement from that note and those tests, in idiomatic Rust.
- Link PlaneGCS and OndselSolver as C++ in worker processes. Don't port them.

## Writing code

- No C++ in the app process. OCCT, PlaneGCS, and OndselSolver run in worker processes only.
- `unsafe` only in FFI crates. No `unwrap`, `expect`, or `panic!` on paths reachable from user, agent, file, or worker input. Return structured errors (code, feature, elements and their total, parameter, cause, suggestion). Workspace lints enforce this. Tests may unwrap inside `#[test]` functions and `#[cfg(test)]` modules, and integration-test files under `tests/` may allow those lints at their top, and shared test modules (`tests/common/`) may allow `dead_code` at their top. Never add lint allows anywhere else.
- Nothing that reaches results, names, or serialized output may depend on `HashMap` order, time, randomness, or thread scheduling. Use `BTreeMap` or `IndexMap`.
- Never block the UI thread.
- Every capability goes through the core command API, so the UI, MCP, and CLI all reach it.
- Instrument work with `tracing` spans.
- When a UX choice is unclear: **behavior follows SolidWorks, visuals and UI follow Fusion 360** (written down from their help in docs/ux/solidworks.md and docs/ux/fusion.md). Never copy FreeCAD's UX.

## Testing

Tests stand in for line-by-line human review, so they have to be able to fail.

- Every behavior change comes with tests whose expected values come from an independent source: an analytic result, a hand calculation, or FreeCAD as an oracle.
- Never weaken, delete, or `#[ignore]` a test to get to green. `tests/oracle/`, `tests/golden/`, `tests/determinism/stress-reference.json`, `tests/determinism/sketch-stress-reference.json`, `tests/determinism/oracle-reference.json`, and every crate's `tests/contract/` (the JSON shapes agents rely on) are protected: stop and ask before changing anything there.
- After implementing or porting something, run `/break-it` on it.
- Before merging, run `/adversarial-review`. It fixes confirmed findings and repeats rounds until the council approves, or it escalates to the maintainer. At the end of a milestone, run it with `--milestone`.

## Git

- One short-lived branch per task, off `main`. Squash-merge only after `/adversarial-review` approves. Never rewrite `main`.
- Conventional commits. The scope is the crate name without the `silico-` prefix: `feat(sketch): …`, `fix(kernel): …`, `docs: …`.
- Commit subjects say what the project gains. No version numbers in subjects.

## Commands

```bash
pixi run occt      # build OCCT with the deterministic recipe (about 3 minutes when inputs change;
                   # builds are shared between checkouts in ~/.cache/silico/occt, or $XDG_CACHE_HOME/silico/occt
                   # or $SILICO_OCCT_CACHE if set; delete it to start fresh)
pixi run test      # OCCT, then the libm shim tests, the OCCT guard and cache tests, the PlaneGCS check, and cargo nextest
pixi run lint      # fmt and clippy, including the libm shim crate
pixi run stress    # 605-case stress test, 10 runs, byte-identical to the committed reference
pixi run gate      # every check on the committed tree: workspace lints, cargo-deny, lint, test, one stress run
pixi run view      # the kernel's parts (a box, fillets, the primitives) in Rerun, edges labelled Edge1, ...
pixi run oracle    # every case in tests/oracle compared with FreeCAD
pixi run oracle-sweep  # 500 generated cases compared with FreeCAD (-- --seed S for others)
pixi run corpus    # real parts (NIST's STEP files, downloaded once) compared with FreeCAD
pixi run mutants -- --in-diff /tmp/change.diff --output /tmp
                   # cargo-mutants on the committed tree, in the gate's worktree (tests/mutants.sh), never
                   # in a checkout: every workspace test for each mutant (.cargo/mutants.toml), but the
                   # few that hold to a wall clock, which fail a loaded baseline. Arguments go to cargo
                   # mutants, paths absolute (git diff main...HEAD > /tmp/change.diff first; -p to
                   # narrow it). CI shards it over the runners (.github/workflows/mutants.yml):
gh workflow run mutants.yml --ref main -f ref=SHA -f base=main
                   # the same on CI; -f packages="silico-core", -f files="PATHS" (from the repository's root,
                   # globs allowed), -f shards=N (the fewest: the plan adds shards, up to 16, so none runs past
                   # about 12 hours), -f long=true for a milestone's or a whole crate's run, which takes runners
                   # of its own so a PR's run never waits behind it; a full SHA as the ref, so a push mid-run
                   # can't mix commits
```

Run C++ builds through pixi so the pinned clang is used. `pixi run gate` runs every check on the committed tree and must pass before a merge. `silico check FILE` checks a document, `silico fmt FILE` writes it in canonical form with its fingerprints and its sketches as solved, `silico export FILE OUT.3mf` (or `OUT.step`) exports its bodies, and `silico serve [--workspace DIR]` runs the MCP server over stdio for an agent (docs/cli.md, docs/mcp.md).
