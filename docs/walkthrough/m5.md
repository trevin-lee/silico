# M5 walkthrough: the bracket built in the app

This is written for you, the maintainer, not for agents. It walks through M5.12's done test: M4.9's L-bracket built in the app from its written spec, by the app's own controls alone, then saved and exported for printing. The scripted session is [crates/silico-app/tests/slice.rs](../../crates/silico-app/tests/slice.rs). The spec is [crates/silico-cli/tests/bracket/spec.md](../../crates/silico-cli/tests/bracket/spec.md), the same one the agent in [m4.md](m4.md) worked from. The design is [docs/design/m5.0-app.md](../design/m5.0-app.md); the row is [docs/roadmap/m5-app.md](../roadmap/m5-app.md), M5.12.

## The spec

As in [m4.md](m4.md#the-spec):
- **The legs:** a base leg 60 × 40 × 5, and an upright 5 thick, 40 wide, up to z = 50.
- **The holes:** two M5 clearance holes (5.5 across) through each leg, 16 apart.
- **The fillet:** the inside corner, filleted at radius 5.

By hand, V = 22,000 − 401.25π ≈ 20,739.4359 mm³.

## The session, step by step

The scripted session drives the app as a person does: clicks, keys and typed text, through the window's accessibility tree and the canvas's own pointer events. It runs on the real kernel, sketch and STEP workers, with the viewport drawn on Mesa's lavapipe in a 1280 × 800 window. It never calls the command API itself; it only reads the app's state to find where things are and to check what happened. A click on the canvas goes where the frame's own camera shows the place. It takes about two and a half minutes: three runs on 2026-11-09 took 155.9, 152.6 and 155.0 s, each sketch about 31 to 42 s of it.

1. **New part** (Command+N): a tab named "Untitled", with no file until its first save.
2. **The L profile, Sketch 1 on XZ** (its x along +X, its y along +Z):
   - CREATE > Create Sketch, then the XZ plane chosen.
   - Front view (Command+1), which looks along +Y, face-on. On an empty part the view fits an empty box about the origin, so the L's right end falls under the Sketch Palette and its top under the sketch bar. A person pans: the session drags the canvas with the middle button, from the middle of the room the overlays leave, so the L's middle comes there. The L then needs no wheel notch.
   - The Line tool (L): the six corners clicked where the canvas shows them, (0, 0), (60, 0), (60, 5), (5, 5), (5, 50) and (0, 50), then (0, 0) again, which shares the first point and ends the chain.
   - The tools infer eight relations as they draw: the first corner level and plumb with the origin (`horizontal_points` and `vertical_points`), the corners at (60, 0) and (0, 50) `on` the x and y axes, and lines 2 to 5 `horizontal` or `vertical`. Lines 1 and 6, along the axes, get no direction of their own: their ends on the axes already hold them so (#431 leaves out a relation the sketch already implies). Nothing is redundant, so the solve flags nothing and the sketch has no warning.
   - Smart Dimension (D) on four lines, each picked, its dimension placed beside it, and its value typed into the Modify box, which takes the keyboard as it opens: 60 (line 1, along the x axis), 5 (the base's end), 5 (the upright's top) and 50 (line 6, along the y axis). Enter places each. No over-define prompt opens.
   - The sketch is fully defined, with 0 degrees of freedom, and the Sketch Palette says so.
   - Finish Sketch on the sketch bar, then F2 on the timeline to name it "Bracket profile".
3. **The legs:** "Bracket profile" clicked in the browser, then CREATE > Pad. Length 10 retyped to 40, and Reversed ticked (XZ's normal is −Y; the part goes +Y). OK. Named "Legs" with F2.
4. **The base's holes, Sketch 2 on XY:**
   - Create Sketch on the XY plane, then Top view (Command+5), fitted to the legs. The session pans as before, then turns the wheel out two notches, so every dimension's place is clear of the overlays.
   - The Circle tool (C): each centre clicked, (40, 12) then (40, 28), then a place on its rim 2.75 to the right. The second centre lines up above the first, which the tool had just added, so the tool infers one relation, `vertical_points`.
   - Smart Dimension: each circle's diameter, 5.5 (two diameters, since Equal isn't built); the origin to the first centre, 40 across and 12 up; and the two centres, 16 apart. Fully defined. Named "Base holes".
   - "Base holes" clicked in the browser, then CREATE > Pocket: Extent Through all, and Reversed ticked (the legs stand above XY). OK. Named "Base holes".
5. **The upright's holes, Sketch 3 on YZ** (its x along +Y, its y along +Z): the same, in Right view (Command+4), panned and one wheel notch out; the centres at (12, 35) and (28, 35), the second level with the first (`horizontal_points`); dimensioned 5.5 and 5.5, 12 and 35 from the origin, and 16 between. Fully defined, named "Upright holes"; then its pocket, Through all, Reversed, named "Upright holes".
6. **The inside corner:** Isometric view (Command+7), which shows the front, the right and the top. The inside corner's edge, from (5, 0, 5) to (5, 40, 5), is clicked at its middle, where the renderer draws (5, 20, 5), at (495.3, 463.3) in the window, and lavapipe's ID buffer picks it: the selection is that one edge, by the name the fillet will store. It's a concave edge, which #424 made pickable (each edge is drawn again for picking a little toward the eye, so the two faces it joins no longer hide it). Then MODIFY > Fillet, which takes the edge from the selection: Radius 1 retyped to 5, OK. Named "Inside corner".
7. **Save As** from the File menu, the path typed as `bracket.silico` (the test's harness has no native dialogs), then Rebuild All (Command+Shift+B): every feature built again from the stored coordinates, with no problem.
8. **Export** from the File menu's Export, three times: a 3MF at the dialog's default tolerance, 0.1 mm; then STEP; then STEP again with the path typed as `bracket.stp`.

## What the session checks

Every expected value is worked by hand or read by FreeCAD 1.1.3, never taken from the app.

- **After each sketch:** fully defined with 0 degrees of freedom; its points and its circles' radii the spec's, exactly; nothing flagged by the solve's diagnosis; and no over-define prompt opened for any dimension.
- **After each feature:** every feature on the timeline built with no problem, and the document with none. Sketch 1 has no warning.
- **Each solid's fingerprint against the agent's bracket, feature for feature.** The reference is the recorded MCP session's seven features ([crates/silico-core/tests/common/bracket.rs](../../crates/silico-core/tests/common/bracket.rs)), written to a file and formatted by a core session of the test's own on the same kernel, as [bracket.rs](../../crates/silico-cli/tests/bracket.rs) does. The saved document's pad, two pockets and fillet, in timeline order, each equal the reference's field for field: volume, area, centre, box, and face, edge and vertex counts. A fingerprint holds no ID, name or sketch member, so the app's own IDs and the names typed with F2 don't enter it.
- **Each solid against the hand,** in both documents: the legs 21,000 mm³ and 9,850 mm², 8 faces, 18 edges, 12 vertices; each pocket two cylinders of 37.8125π mm³ less, and 24.75π mm² more area; the bracket 22,000 − 401.25π mm³ and 9,500 + 137π mm², 13 faces, 33 edges, 22 vertices; every box [0, 0, 0] to [60, 40, 50]; and each centre by the hand's sums ([crates/silico-cli/tests/common/hand.rs](../../crates/silico-cli/tests/common/hand.rs), shared with bracket.rs).
- **The sketches:** each stores the recorded session's points and radii, exactly, on the same plane. The constraints differ, since the tools write their own relations (and two diameters where the agent wrote a diameter and `equal`); the geometry they solve to doesn't.
- **The fillet's edge:** its stored name is the pad's edge generated from the L's corner at (5, 5), built from the UI document's own IDs: `<pad>.pad.Edge(G <sketch 1>.sketch.Vertex.<that point>)` (in one run, `gk192why.pad.Edge(G herz2b1f.sketch.Vertex.yj3vetr0)`), its radius 5 and its base the second pocket.
- **The 3MF,** read from its bytes as [m4.md](m4.md#what-the-replay-checks)'s is: one object, named "Inside corner", closed, manifold, consistently oriented and facing outward; 1,084 vertices and 2,180 triangles (each rim 126 chords and each fillet arc 32, by OCCT's rule at 0.1 mm, counted by hand); its box the part's exactly; and its volume the part's plus the chords' segments, within 32-bit rounding.
- **The STEP,** read back by FreeCAD with `Part.read` and `Import.insert`, as [silico-oracle's STEP tests](../../crates/silico-oracle/tests/step_oracle.rs) read theirs: its volume and area the hand's within the measure's bound and the file's digits; 13 faces, one solid, valid; its box and centre the part's within 1e-9 of the box's diagonal; and the product's label "Inside corner".
- **`.stp` and `.step`:** the same bytes.
- **The window never waited** on a command (`never_waits::waits() == 0`).

To run it, build the workers, then the test (it needs pixi's lavapipe and the FreeCAD oracle, `pixi install -e oracle`):

```bash
pixi run cargo build --workspace --bins
pixi run cargo nextest run -p silico-app -E 'test(the_bracket_built_in_the_app)'
```

## What the app can't do yet

Each is a finding from building the slice. None stopped the bracket.

- **The constraint tools** (Horizontal, Equal and the rest) aren't built ([toolbar.rs](../../crates/silico-app/src/toolbar.rs), `Does::NotBuilt`), so the holes take two diameters where the agent wrote `diameter` and `equal` (G3). The geometry is the same.
- **In sketch mode, no Look At, and Fit frames the bodies, not the sketch** (G6). On an empty part, Front fits an empty box about the origin, so the L's right end falls under the Sketch Palette and its top under the sketch bar. A person pans and turns the wheel, as the session does: after the pan, sketch 1 needs no wheel notch, sketch 2 two notches out, and sketch 3 one.
- **No sketch on a face from the canvas** (G7): Create Sketch offers the origin planes, and the canvas's right-click menu has no Sketch on this face yet. The bracket sketches on origin planes, so the slice doesn't need it.
- **No Measure tool and no render** (G8): INSPECT > Measure isn't built, so the app gives no body's volume as `mass_properties` does; the selection view shows a selected element's measures, and two elements' distance and angle (#414), which would read the hole's 17.25 from the end face. Nothing in the app writes a PNG as `render` does.
- **Default names** (G12): features are named Sketch1, Pad, Pocket and so on until renamed. Two pockets would both read "Pocket"; the session names each with F2 as it's made, so the 3MF's object and the STEP's product read "Inside corner".
- **Accessibility:** the ViewCube's and the Navigation bar's groups have no bounds in the accessibility tree (the Navigation bar's are NaN), so the session bounds each by what it holds (N2's other half; the sketch bar's and the palette's came with #425).
