# M0 walkthrough: what's under Silico, and how to check it yourself

This is written for you, the maintainer, not for agents. It explains what M0 built, how the pieces fit, and how to see each one work with your own eyes. The roadmap ([m0-foundations.md](../roadmap/m0-foundations.md)) has the full detail and every test; this is the map.

## The one-paragraph version

Silico's app never runs C++. When it needs geometry, it sends a small message to a separate **worker process**, which calls **OpenCascade** (OCCT) and sends the result back. If OCCT crashes (and it can), only the worker dies; the app gets an error and carries on. OCCT is built in a special way so the same request gives **bit-identical** results on every machine, which is what lets Silico store models as a list of features and rebuild them anywhere. Every step is tested, and the end-to-end test checks a fillet against FreeCAD.

## A request, end to end

Here's what happens when Silico fillets an edge (this is the M0 exit test, [crates/silico-kernel/tests/fillet.rs](../../crates/silico-kernel/tests/fillet.rs)):

```
 app process (Rust only)                         worker process (Rust + OCCT)
 ───────────────────────                         ────────────────────────────
 silico_core::worker::Worker                     silico-kernel-worker
   call(Op::Fillet{shape, edges:[1], r:2})
     │  encode: postcard, 4-byte length    ──►   read frame, decode Request
     │  over a Unix socket (fd 3)                 worker::handle(op)
     │                                              from_brep(bytes)  ← check CRC
     │                                              fillet(shape, [1], 2.0)
     │                                                → C++ bridge → BRepFilletAPI
     │                                                → Rust: is the result valid?
     │                                                  (else invalid_result)
     │                                              to_brep(result) + CRC
     │  decode Response, check id + generation ◄── write frame
     ▼
   Ok(Reply::Shape(ShapeData::checked(brep, valid)))  or  Err(structured Error)
```

The shape never stays in the worker: it travels as bytes (OCCT's binary B-rep plus a checksum), with whether it's valid, which the worker that made it checked once (a shape from a file goes as "unchecked", and the worker checks it). So workers keep no state, any worker can do any request, and a crashed one is simply replaced; and no shape is checked as a whole twice.

## The pieces

| Piece | What it does | Where |
|---|---|---|
| **Deterministic OCCT build** | Builds OCCT 7.9.3 (the release Silico's FreeCAD reference runs) from source with a pinned compiler and flags, so results don't depend on the machine. | [third_party/occt/build.sh](../../third_party/occt/build.sh), [ARCHITECTURE.md](../../ARCHITECTURE.md) (*Deterministic kernel*) |
| **Math shim** | Replaces the platform's `sin`, `pow`, and friends (which differ in the last bit between macOS and Linux) with one pure-Rust library everywhere. | [third_party/occt/libm-shim/](../../third_party/occt/libm-shim/) |
| **Shared build cache** | One OCCT build per set of inputs, shared by every checkout and worktree, so a new worktree gets OCCT in seconds instead of 3 minutes. | [third_party/occt/scripts/cache.sh](../../third_party/occt/scripts/cache.sh) |
| **C++ bridge** | The only C++ Silico wrote: thin calls into OCCT that make shapes, fillet them, measure them, and mesh them, and report facts for Rust to decide on. Every C++ exception comes back as a Rust error. | [crates/silico-kernel/cpp/](../../crates/silico-kernel/cpp/), [src/lib.rs](../../crates/silico-kernel/src/lib.rs) |
| **Protocol** | The messages between the app and workers, and how they're framed on the socket. A worker's first frame is empty: it says the worker has started, so a crash before it is the install's, not the request's. Fuzzed with 50 million random inputs. | [crates/silico-protocol/](../../crates/silico-protocol/) |
| **Worker** | The process that runs OCCT: reads requests, calls the bridge, writes replies, checks floating-point traps after every request. | [crates/silico-kernel/src/worker.rs](../../crates/silico-kernel/src/worker.rs) |
| **Worker client** | The app's side: starts a worker, sends requests with a timeout, turns crashes, hangs, and garbage into errors, and forwards the worker's logs. | [crates/silico-core/src/worker.rs](../../crates/silico-core/src/worker.rs) |
| **Structured errors** | Every failure has a stable code (`kernel_failed`, `worker_crashed`, ...), the feature and element at fault, the cause, and a suggestion. Agents read the JSON form. | [crates/silico-core/src/error.rs](../../crates/silico-core/src/error.rs) |
| **Debug viewer** | Shows what the kernel builds, in Rerun, with edges labelled. | [crates/silico-view/](../../crates/silico-view/) |
| **The gate** | One command that runs every check on the committed code. Must pass before a merge. | [tests/gate.sh](../../tests/gate.sh) |

## How to check it yourself

Each of these is something you can run and judge, rather than take on trust.

1. **See the geometry.** `pixi run view` opens Rerun with a box, the box with Edge1 filleted, and the box with every edge filleted. Each part's summary (volume, faces, validity) is beside it. Hover an edge to see its number: `Edge1` is the same edge in FreeCAD.
2. **Compare with FreeCAD yourself.** In FreeCAD's Python console: `b = Part.makeBox(10, 20, 30); f = b.makeFillet(2, [b.Edges[0]]); f.Volume` gives 5974.247779607694, the same number Silico's summary shows.
3. **Watch a crash be contained.** `pixi run test` includes tests where the worker segfaults, aborts, hangs, and sends garbage; each comes back as an error naming what happened, and the test process carries on. They're in [tests/worker.rs](../../crates/silico-kernel/tests/worker.rs) (`segfault_becomes_error` and its neighbours).
4. **Check determinism.** `pixi run stress` runs 605 random OCCT operations 10 times and compares every result, bit for bit, with [tests/determinism/stress-reference.json](../../tests/determinism/stress-reference.json), which was produced on Linux and matches macOS exactly.
5. **Break something and watch the gate catch it.** Change an expected value in a test, commit it on a branch, and run `pixi run gate`.

## What's tested against what

Tests only mean something if their expected values come from somewhere other than the code. In M0:

- **Analytic values:** the box's volume (6000), the fillet's volume and area worked out by hand (6000 − (4 − π)·30), a unit cube's fillet area, a mesh's enclosed volume.
- **FreeCAD as an oracle:** fourteen fillets, compared on volume, area, centre, topology, and validity. Where FreeCAD returns an invalid solid (a bug it reintroduced in 2024; see [docs/ports/fillet.md](../ports/fillet.md)), Silico refuses it, and the test records the difference.
- **A committed reference:** the 605-case stress output.
- **Mutation testing:** for each change, `cargo mutants` (and hand-made mutants for C++ and shell) deliberately breaks the code to prove a test fails. The survivors are listed in the roadmap with the reason each is acceptable.

## Limits worth knowing

- **Only a few operations exist:** box, fillet, summarize, mesh. Extrude, revolve, booleans, and chamfer come in M1.
- **No document, no names yet.** "Edge1" is OCCT's numbering, which changes when the model changes. Stable names (topological naming) are M2's job, and the biggest risk in the whole project.
- **Some rules are left to review, on purpose:** an `allow` that lowers a lint, C++ a third-party crate compiles itself, and a few other guards against mistakes nobody has made yet. The roadmap's M0.3 section lists them.
- **No CI yet:** checks run on your Mac (and were run by hand on Linux in a VM). M0.9 adds CI on your workstation when the GitHub repository exists.
- **Rerun collects anonymous usage analytics** by default; `rerun analytics disable` turns that off.

## Words

- **B-rep** (boundary representation): a solid described by its faces, edges, and vertices. OCCT's native format.
- **Worker:** a separate process that runs OCCT, so a crash can't take the app down.
- **Oracle:** an independent implementation (here FreeCAD) used to check answers.
- **Mutant:** a deliberately broken copy of the code; a good test suite fails on it.
- **Deterministic:** the same inputs give the same output bits, on every machine.
- **Deflection:** how far a display mesh may stray from the true surface.
