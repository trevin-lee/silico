# M4 – MCP, before any UI

**Status: draft.** Written from ROADMAP.md's M4, ARCHITECTURE.md's Agent interface, and the items the M2 milestone review left for M4 (MA2, MA3, and a command to bypass or clear the cache). It stays a draft until M3 closes; then the maintainer takes the open decisions, and M4.0's study notes detail the steps. M4.1's design changes contracts (the command API's JSON shapes, which MCP's tools are), so it starts from a design the maintainer approves, as M2.1 and M3.2 did.

**Goal:** an agent does everything headless that the app will let a person do: opens a document, edits it inside a transaction it can roll back, finds elements by stable name, measures them, sees the part as a PNG, reads the logs when something fails, and exports what it made. The MCP server is a client of the core's command API (`silico_core::command`) and does nothing the API can't.

**Exit tests:** an agent designs a bracket headlessly through MCP and exports a printable 3MF (M4.9); every tool's JSON shapes are protected contracts; the MCP server survives the `/break-it` catalog's garbage MCP calls; and the council approves with `/adversarial-review --milestone`.

## Study

- **`docs/ports/mesh-export.md`**, from FreeCAD's mesh export: `src/Mod/Mesh/App/Exporter.cpp` and `AppMeshPy.cpp` (the export tolerance, 0.1 mm by default, `MaxDeviationExport`), `TopoShape::getFaces` (how a solid's faces are meshed and their points merged), `src/Mod/MeshPart/App/Mesher.cpp` (`createStandard`: `BRepMesh_IncrementalMesh` with linear and angular deflection), `src/Mod/Mesh/App/Core/IO/Writer3MF.cpp`, and the solid check it uses (`MeshEvalSolid`, `Core/Evaluation.h`). Their history, including `7bbc93e218` (3MF files FreeCAD wrote as `type="surface"` that PrusaSlicer wouldn't take, issue #10075) and `49c80ebe5c` (each object's name in the 3MF). It settles what a printable mesh is (closed, manifold, oriented outward, no degenerate triangles) and how close it must stay to the B-rep.
- **`docs/ports/measure.md`**, from FreeCAD's Measure module (`src/Mod/Measure/App/`: `Measurement.cpp` and the `MeasureDistance`, `MeasureAngle`, `MeasureLength`, `MeasureArea`, `MeasureRadius`, `MeasureDiameter`, `MeasurePosition`, `MeasureCOM` types), its tests (`tests/src/Mod/Measure/`), and its history, at FreeCAD 1.1.3, the oracle's release: what each measure means for each pair of element kinds, and the cases it refuses.
- **The MCP specification**, at the revision M4 pins: tools, structured tool results, resources, and stdio transport; and which Rust SDK to use (the official `rmcp`, if it passes cargo-deny and the review).

## Steps

| Step | Builds | Key tests |
|---|---|---|
| M4.1 Command API design | A design for the maintainer first (`docs/design/m4.1-command-api.md`): every command the agent interface needs, each with its request, its result, and its errors as JSON; how a client holds an open document (a session); transactions (decision 1); edits as commands and as text (decision 3); how an external change to the file is met (decision 2); and how the shapes are versioned. The command API's shapes are the MCP tools' shapes, one to one, so the CLI and the app read the same ones | The design's examples, parsed and written back byte for byte once M4.2 exists; the shapes' JSON Schemas snapshot under `crates/silico-core/tests/contract/` (protected, with the maintainer) |
| M4.2 Sessions and per-client generations | `command::Session`: one open document, its checked form and its model, rebuilt in the background on a kernel shared with other sessions. The pool's generations become per client (MA2): each session holds its own handle, and a newer generation supersedes only its own client's work, never another session's. Transactions as decision 1 settles: begin, commit, rollback, the document's bytes and model restored exactly on rollback | Two sessions on one pool: a new generation in one never drops or stops the other's work (the fake kernel's call record, and the pool's own tests with launch logs, as M1's are); rollback restores the document's bytes and the model's fingerprints exactly; a rollback after a failed rebuild restores the last good model; a commit with nothing changed writes nothing; a session dropped mid-rebuild leaves no partial state (M2.4's test, for sessions) |
| M4.3 Cache control | A command to rebuild without the cache's reads (`fresh`, still writing what it builds) and one to clear a document's cache (`cache clear`: only the files the cache made, never another file in `.silico-cache/`, never through a link), and their CLI forms (`silico check --fresh`, `silico cache clear`) | A fresh rebuild builds every step (the fake kernel's call record) and leaves entries that a later rebuild hits; clearing removes every entry and nothing else (a stray file and a link out of the directory are left alone); clearing while another process rebuilds leaves no entry that's trusted half-written (M2.5's corrupt-entry tests) |
| M4.4 Elements and queries | A command that lists a model's elements (MA3): each face, edge, and vertex by its stable name, with its kind, its geometry type (plane, cylinder, cone, sphere, torus, B-spline; line, circle, ellipse, B-spline), and its measures (a face's area, its normal at a point on it where it's planar, an axis and radius where it has one; an edge's length; a vertex's position). The worker returns these as raw measures from OCCT (a new request, `describe`), and the core names and orders them. Queries are structured filters over that list (decision 4): kind, type, a direction a planar face faces within an angle, ranges of measures, an order, and a limit, so "the largest planar face facing +Z" is a filter, not a phrase. A query never picks among ties: where the elements it would choose between are equal within the measure's tolerance, it returns all of them and says so. And `silico schema`, the document's JSON Schema, for agents to discover the format | A box's six faces listed with their analytic areas and normals; a cylinder's side as a cylinder of its radius about its axis; names the same as the element map's (M2.7), every one; "largest planar face facing +Z" on a stepped block finds its top face by name, and on a box with two equal top faces returns both, as tied; a filter naming a kind or type that doesn't exist is refused, naming the field; the list's order holds across runs and platforms (the determinism sweep); `silico schema` is the committed schema snapshot, exactly |
| M4.5 Measurement | Mass properties of a solid (volume, area, center of mass, as M1 measures them as FreeCAD does) and the Measure module's measures, as `docs/ports/measure.md` finds them: distance between two elements (the least, and the points where it's met), the angle between two planar faces or two lines, an edge's length, a circle's or a cylinder's radius and diameter, a vertex's position. Each takes elements by stable name; a name that finds nothing is `reference_broken` with candidates (M2.8), never a guess | Oracle cases against FreeCAD 1.1.3's Measure for each pair it supports (protected); analytic cases: a box's opposite faces at its height, a hole's wall's radius, the angle between a wedge's faces; a measure FreeCAD refuses for a pair of kinds is refused, naming both elements; non-finite or degenerate results never leave the worker |
| M4.6 Offscreen PNG | A PNG rendered without a window, in `silico-render` (the crate M5's viewport grows from, on `re_renderer`): from a named view (Fusion's: front, back, top, bottom, left, right, and the isometric corners) or any camera, at a size the request gives within a limit; faces shaded by the kernel's normals and edges drawn crisp; elements highlighted by name; the image's camera returned with it so an agent can ask for the next view. Rendering is never on a thread a client waits on without a timeout. How renders are tested, given GPUs differ, is decision 5 | Through an ID buffer, not compared pixels: a box from the front shows exactly its front face's ID over the rectangle its projection covers (analytic, to a pixel at its edges); a highlighted face's pixels are the highlight wherever that face is visible and nowhere else; a camera inside the part, a zero-size image, and a size over the limit are refused, naming the field; a render on a machine with no GPU uses the software rasterizer, or refuses with an error that says so |
| M4.7 Logs | `read_logs`: the core keeps each session's recent `tracing` events, the workers' re-emitted ones included, in a bounded buffer, each with its span (the command, the feature, the kernel request, as ARCHITECTURE.md's Errors and logging traces them), read by level, span, feature, and a cursor, so an agent reads only what's new. The buffer's bound is in events and bytes; what it drops it counts and says | A failed fillet's logs, read by its feature's ID, hold the kernel request that failed and the worker's own lines; a cursor read twice returns nothing new; a flood of events keeps the buffer within its bound and says how many it dropped; one session's logs never show another's |
| M4.8 Export | 3MF, as `docs/ports/mesh-export.md` finds it: each solid tessellated within the export tolerance (FreeCAD's 0.1 mm by default, given by the request within limits), its triangles joined into one closed mesh at the edges the faces share, checked closed, manifold, and oriented outward before it's written, and refused otherwise, naming the faces at fault; written as `type="model"` in millimetres, each object named by its feature, the archive's bytes deterministic (fixed entry order and times). STEP export comes with it or later, as decision 6 settles. Export goes through the command API, so the CLI's `silico export` is a thin client of it | A box's 3MF has 12 triangles and 8 vertices, and its volume is the box's exactly; a cylinder's mesh volume is within the tolerance's analytic bound of πr²h; FreeCAD 1.1.3 reads every exported 3MF back as a solid with the volume Silico measured (an oracle case); the bytes of one export are identical across runs and platforms; a solid whose mesh comes out open (a face OCCT couldn't mesh) is refused, naming the face, never written as a surface |
| M4.9 The MCP server and the bracket | A `silico-mcp` crate and `silico serve`: the command API as MCP tools over stdio (decision 7), each tool's input and output schema from the same types as the command API's, its errors as the core's structured errors (code, feature, elements and their total, parameter, cause, suggestion, candidates). The server reaches only the workspace it was started in: a path outside it, or through a link out of it, is refused. The bracket: a scripted MCP client replays a recorded agent session that designs an L-bracket from a written spec (two legs, holes for M5 screws in each, the inside corner filleted), rolls back one wrong edit, renders it, measures it, and exports it; and the maintainer runs the same spec with a fresh agent that has only the MCP server, recorded in `docs/walkthrough/m4.md` | The replayed session's 3MF passes M4.8's checks, its volume is the bracket's by hand calculation within the tolerance's bound, and FreeCAD reads it back as a solid; every tool's schema snapshot in `crates/silico-mcp/tests/contract/` (protected); the `/break-it` catalog's garbage MCP calls (malformed JSON-RPC, unknown tools, wrong types, huge arguments, calls during a rebuild, a client that disconnects mid-call) never crash or hang the server and each gets a structured error; the live agent's session, as recorded, exports a 3MF that PrusaSlicer slices |

## Open decisions

Each with a recommendation, for the maintainer when M3 closes.

1. **What a commit does** (M4.2). A transaction could end in the session's memory, with saving a separate command, or end on disk. Recommended: a commit saves the document through `file`'s safe save, and a rollback never touches the disk, so the file only ever holds committed states and git sees nothing half-done; outside a transaction, each edit is its own transaction, applied and saved at once, as an edit in SolidWorks applies at once. One transaction at a time per session, not nested.
2. **A file changed outside the session** (M4.2). Agents may edit the text directly (ARCHITECTURE.md), so a file can change under a session. Recommended: outside a transaction the session reloads it through the gate, as the app will; inside one, the commit is refused as a conflict, naming the file, and the agent rolls back or begins again from the file's new state. Nothing merges silently.
3. **Edits as commands and as text** (M4.1). ARCHITECTURE.md's workflow edits the timeline as text or through commands. Recommended: both, from M4: a command that replaces the document's text (through the gate), and typed commands for the edits the bracket needs (add a feature, set a feature's field, remove a feature, each naming what it touches by ID), which M5's UI then uses. Each goes through the gate, so a bad edit is refused whole.
4. **How queries are written** (M4.4). Recommended: structured JSON filters, not a phrase language, so a query means one thing and its errors name a field; an agent turns "largest planar face facing +Z" into one. A tie is never broken by name or position: the query returns every tied element and says so.
5. **How renders are tested** (M4.6). GPUs and drivers differ, so a PNG's bytes aren't the same everywhere, and renders reach no result, name, or file, so the determinism rule doesn't bind them. Recommended: tests read the ID buffer and check it against the projection by hand, never compare pixels against stored images; CI renders with a software rasterizer (Mesa's on the Linux runner), pinned in pixi.
6. **STEP export** (M4.8). The vertical slice needs STEP and 3MF export from both the UI and MCP; ROADMAP.md's M4 names 3MF only. OCCT's STEP writer puts the time and the system's name in the header, and FreeCAD import needs a deterministic STEP writer too. Recommended: STEP export in M4.8, its header written from the document so its bytes are deterministic, and the same writer later serves FreeCAD import.
7. **Transport** (M4.9). Recommended: stdio only in M4, one client per server process, as an MCP client starts it; no network listener, so nothing is exposed. Several sessions in one process (several documents) still share one pool, which is why M4.2 makes generations per client. A network transport, with authentication, waits until something needs it.
