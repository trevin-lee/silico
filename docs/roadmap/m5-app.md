# M5 – The app

**Status: draft, for the maintainer at M4's close.** Written from ROADMAP.md's M5, ARCHITECTURE.md (invariants 3 and 4, *Rendering and UI*, and the drag rules planned for M5 under *Process model*), the M4.1 design's notes on what M5 owes (decisions 1, 9, 29, 30, and 33, and section 9's table of the app's commands), M4.6's render design, and what M4 left open. The open decisions at the end each carry a recommendation; M5.0 turns the ones the maintainer takes into a design for the maintainer to approve before the app is built, as M4.1 did for the command API.

**Goal:** a person does in a window what an agent does through MCP: opens a document, sketches on a plane or a face, pads, pockets, revolves, fillets and chamfers, sees each rebuild as it lands, picks faces and edges by clicking them, undoes, saves, and exports a 3MF or a STEP file. The app is one client of the core's command API (invariant 3), in a process of its own beside any `silico serve` (decision 30's (a)), and its UI thread never waits on a rebuild, a worker, or a file (invariant 4). Visuals and UI follow Fusion 360; behavior follows SolidWorks; nothing copies FreeCAD's UX.

**Exit tests:** the vertical slice end to end in the app, driven by a scripted UI test that builds the M4.9 bracket from the same spec, and its 3MF and STEP pass M4.8's checks with the bracket's volume by hand; the same bracket built through MCP rebuilds to the same fingerprints; the UI keeps drawing frames while a rebuild, a drag, and an export are held in the fake kernel; every new capability is a command first, with its contract snapshot, so MCP reaches it too; the maintainer builds the bracket in the app by hand, recorded in `docs/walkthrough/m5.md`; and the council approves with `/adversarial-review --milestone`.

## Study

- **SolidWorks' behavior, written down** (`docs/ux/solidworks.md`), from SolidWorks' own help and its documented behavior, never from guesses: selection and pre-selection (what highlights on hover, what a click, a Ctrl-click, and a box select take, and the selection filters); sketch inference and automatic relations (horizontal, vertical, coincident, tangent, midpoint, and when each is offered); dragging an under-defined sketch; how features react to an edit upstream, and rebuild and error feedback (the tree's error and warning marks, *What's Wrong*, a feature that fails but leaves the rest); undo and redo (what's undoable, and across what); the unsaved state, Save, and a file changed on disk while it's open. Each item is one line of behavior and its source, so a test can be written from it.
- **Fusion 360's layout, written down** (`docs/ux/fusion.md`): the browser tree, the timeline bar and its marker, the toolbar's workspaces and tabs, feature dialogs docked at the right with in-canvas manipulators, the view cube and the navigation bar, and the look (density, colour, type), as `re_ui` builds it. Screens are described, not copied.
- **The viewport on `re_renderer` 0.38.1,** from Rerun's viewer, which embeds it in egui the way the app will: how its view builder draws into an egui paint callback, its outline and picking passes, and what crisp edges, silhouettes, and hidden-line display need beyond what M4.6 drew. And the per-instance picking ID M4.6's design flagged (each face a draw of its own), measured on the largest parts the corpus has.
- **The toolkit's versions:** egui, `eframe`, `egui_tiles`, and `re_ui` at the versions `re_renderer` 0.38.1's release pins, so one `wgpu` (30) serves the viewport and the UI, through `cargo-deny`.
- **`egui_kittest`,** egui's test harness: driving the app through its accessibility tree (find a button by its label, click it, read a panel's text) without comparing pixels.
- **`docs/ports/sketch-edit.md`,** from FreeCAD's sketch editing, for behavior only (what each operation does to the geometry and its constraints, never its UX): `SketchObject::trim`, `split`, `fillet` (a sketch corner), `delConstraintOnPoint`, and how a shared point is split; their tests and the bug fixes in their history. Silico's shared points (M3.2's D2) decide the rules where FreeCAD's differ.

## What M4 leaves for M5

- **Sketches on faces (A4).** Not built in M4: the bracket sketches on origin planes. M5.8 builds it, before sketch mode needs it, on Fable's F1 and F2 (the maintainer's veto open). If the maintainer drops A4 at M4's close, M5.8 goes and `elements` loses `default_x`, as the M4.1 design says.
- **`.stp`.** Export takes only `.step`; FreeCAD and SolidWorks take both. Recommended at M4's close as a small follow-up; if it isn't done by then, M5.11 does it.
- **Inserting, moving, and suppressing features, and the finer sketch edits** (M4.1, section 5's *Not in M4*): M5.1 and M5.9.
- **The pool's rules for drags** (ARCHITECTURE.md, planned for M5): M5.3.
- **The app's undo, unsaved state, and live co-editing** (decisions 9, 1, and 30, each left to M5): open decisions 1 to 3 below.
- **Open lows the app makes matter more,** from the M4 close's carried-forward list. A long-lived window and frequent rebuilds turn these from rare into common, so each is fixed in the step that first leans on it:
  - the refusing pool never retries finding its worker, so an app started before the worker was built keeps the error (M5.4);
  - a hanging `describe` is asked again every rebuild, and a failed batch doesn't cancel those in flight (M5.5, which publishes every rebuild's model);
  - the per-session command queue is unbounded (M5.4: the app coalesces a burst of edits rather than queueing each);
  - the `cancelled` error code, still `internal` for a cancelled render (M4.6's open item), which the app's stop button shows (M5.4);
  - `Candidates::of_name` costs O(B) per broken name, felt where M5.7 shows a broken reference's candidates (a protected contract, so its own PR with the maintainer, if M5.7's benchmark shows it).

## Open decisions

Each with a recommendation, for the maintainer at M4's close.

1. **The unsaved state** (M5.0, M5.4; decision 1 left it to M5). The app could save every edit at once, as M4's edits outside a transaction do, or hold a transaction open as its unsaved changes. Recommended: the app holds one transaction per document as its unsaved state: Save commits it and begins the next, Revert rolls it back, Close asks if it holds edits, as SolidWorks does. The file then holds only what the person saved, and an agent's commits never meet half a person's edit.
2. **Undo** (M5.2; decision 9 left the app's to M5). An undo stack only in the app breaks invariant 3 (the app could do what the API can't); one over committed states is a second history beside git, which decision 9 refused. Recommended: `undo` and `redo` as commands, inside a transaction only, over its edits: the app's Ctrl+Z and an agent's undo are one thing, and once committed, history is git's.
3. **Live co-editing** (M5.0; decision 30). (a) As M4 decided: the app and `silico serve` share a document through its file, the app reloading what an agent commits when it holds no edits, and meeting a change under its edits as decision 2 does (the commit refused as a conflict; the app offers to reload, dropping its edits, or to keep them and save over); (b) `attach`, several clients on one session in one process, so a person watches an agent's edits live, with ownership rules on every command. Recommended: (a) for M5. The slice needs a person and an agent on one part, not at once; (b) can come after, with M4's shapes unchanged, when a reason to watch live appears.
4. **Picking at scale** (M5.6). `re_renderer`'s picking ID is per instance, so each face is a draw of its own: fine at the slice's sizes, thousands of draws a frame on a large part. Recommended: per-instance first, measured on the corpus's largest part in M5.6's benchmark; a per-triangle ID target (a small fork of `re_renderer`, which ARCHITECTURE.md allows for CAD needs, or M4.6's fallback `R32Uint` target) only if the benchmark misses a frame.
5. **Sketches on faces in M5** (M5.8). Recommended: yes, as M5.8, before sketch mode: a SolidWorks user sketches on faces constantly, and A4's frame is decided (F1, F2), its `default_x` already reported. The alternative, origin planes only until after M5, makes the app's sketching unlike every CAD tool.
6. **The viewport's meshes** (M5.5). (a) One mesh for each rebuild, at a deflection relative to each part's size, as FreeCAD's and Fusion's default display quality is; (b) meshed again as the view zooms, finer near the eye. Recommended: (a), with a display-quality setting; (b) only if the slice's parts look faceted at the zooms a person uses.
7. **How the app is tested** (M5.4 on). Recommended: `egui_kittest` through the accessibility tree (labels, roles, values), the viewport through its ID buffer against projections by hand, as M4.6's renders are; never a screenshot compared with a stored image, which GPUs and fonts would break. The UI thread's freedom is tested by a frame counter that keeps climbing while the fake kernel holds a request.
8. **The toolkit** (M5.4). Recommended: `eframe` with its `wgpu` backend, `egui_tiles`, and `re_ui`, at the versions `re_renderer` 0.38.1's release pins, so one `wgpu` and one look serve the viewport, the UI, and agents' renders; the Rerun crates' pin moves only with `re_renderer`'s.
