# M3 – Sketcher

**Status: detailed** from the study, docs/ports/sketcher.md. M3 runs in parallel with M2. M3.2 onward change the document's schema (a protected contract): each such step starts from a design the maintainer approves, as M2.1 did. M3.6 needs M2.7–M2.8's names for sketch edges.

**Goal:** constrained 2D sketches, solved by PlaneGCS in a worker, that turn into faces and drive pad, pocket, and revolve.

**Exit tests:** the ported FreeCAD sketcher and face-maker tests pass, interactive drag latency through the worker is measured, and the council approves with `/adversarial-review --milestone`.

## Study

**`docs/ports/sketcher.md`** (done), from FreeCAD's sketcher (`SketchObject*.cpp`, `Sketch.cpp`, `Constraint.cpp`, `SketchAnalysis.cpp`), PlaneGCS, `FaceMakerBullseye` and `FaceMakerCheese`, PartDesign's profile, pad, pocket, and revolve, their tests, and their history. Its main findings, which shape the steps:
- **PlaneGCS at FreeCAD 1.1.3**, the oracle's release, not main: main changed the solver's semantics (signed distances, how reference values are found, the conflict analysis) and has a status regression 1.1.3 doesn't.
- **Determinism needs more than the recipe:** the solver orders its unknowns by their addresses, and Eigen's matrix products block by the CPU's cache sizes on x86. The worker allocates every parameter from one array in a canonical order, and fixes Eigen's cache sizes.
- **FreeCAD's validation is weak** (out-of-range references hide every constraint; anything else surfaces as "malformed" at solve time), and several choices are made from the current geometry. Silico's format makes each constraint form and each choice explicit, and the gate refuses what doesn't fit.
- **FreeCAD tests almost none of the solve's outcomes** (degrees of freedom, conflicting, redundant): Silico writes those cases by hand count and checks them through the oracle.

## Open decisions

From the study (docs/ports/sketcher.md), each with a recommendation. The maintainer took the recommendation for 1–3 and 5–8 on 2026-10-16; 4 rides with M3.2's format design.

1. **Signed constraints** (M3.2, M3.3). 1.1.3's PlaneGCS has no signed distances or oriented tangents, so a side holds only while the solver doesn't cross over. Main's commits (`3c8a254356`, `f432d1c6a7`, `5a6be36bc3`) could be carried as patches, but the 1.1.3 oracle couldn't check those cases. Recommended: 1.1.3 as it is for M3, the sides stored in the format from the start (so a later patch changes no file), and the patches considered when the oracle moves to a FreeCAD that has them. **Decided (the maintainer, 2026-10-16): as recommended.**
2. **Where nesting is decided** (M3.5). Bullseye's classification runs on OCCT faces. Doing it in the core needs exact point-in-region tests on arcs, ellipses, and B-splines; doing it in the worker puts logic below the boundary ARCHITECTURE.md draws. Recommended: the core decides nesting and refusals from the solved 2D geometry (it has it exactly), and the worker only builds the faces it's told to. **Decided (the maintainer, 2026-10-16): as recommended.**
3. **Several solids from one sketch** (M3.6). FreeCAD allows a pad of disjoint regions (several solids, `AllowCompound`); M2.1's D2 says every feature makes one solid. Recommended: refuse disjoint regions in a pad, naming them, until multi-body features exist. **Decided (the maintainer, 2026-10-16): as recommended.**
4. **How solved coordinates are stored** (M3.2, M3.4). ARCHITECTURE.md says solved coordinates are written in full; lengths in the file are whole nanometres (`Length`). Rounding the solver's `f64` to the nanometre would make the next solve start from other values than the last one ended at. Recommended: decided in M3.2's design, for the maintainer, with M3.4's "unchanged sketch, unchanged bytes" test as its check.
5. **When redundant constraints agree** (M3.3). PlaneGCS calls a constraint redundant if, the others met, its error is under 1e-5 (its squared error under 1e-10), so two dimensions 1e-5 apart are "redundant", and keeping the solve would quietly take one of them. PlaneGCS's residuals aren't in one unit either: millimetres for distances and coincidences, mm² for tangency between circles and arcs (`d² − (r1 ± r2)²`), and a sine or cosine, scaled by how the lines' lengths changed, for parallel and perpendicular; so one tolerance on them means different geometric tolerances for different forms. And a successful solve itself leaves each residual up to about 1e-10 (DogLeg's and Levenberg–Marquardt's own tolerances), so a redundant angle that agrees can be off by several nanodegrees on the solution (the oracle, solving a 30°–60°–90° triangle from 200 starts, left the implied third angle up to 7.2 nanodegrees off). Recommended: keep a redundant-only solve only if the core, measuring each redundant constraint on the solution geometrically (a distance's gap in millimetres, an angle's in radians, a tangency's gap between the curves), finds it met within a tolerance tied to the solver's convergence, not the file's resolution; otherwise report them as conflicting, naming them. The numbers are M3.3's design, checked by oracle cases including that triangle. **Decided (the maintainer, 2026-10-16): as recommended.**
6. **B-spline end points** (M3.3, when B-splines come). In 1.1.3 a periodic spline's end points, and an unclamped end, are free unknowns (two degrees of freedom each), so a periodic spline with every pole fixed is never fully constrained. FreeCAD tried dropping them (`1b59e74568`, 2017) and restored them (`7cd2cbd29c`, 2022): the end points sit on knots, and without them the knot can't be used. Recommended: follow FreeCAD's count, so the oracle agrees, and say so in the format. **Decided (the maintainer, 2026-10-16): as recommended.**
7. **PlaneGCS's patch policy** (M3.1). OCCT's policy (ARCHITECTURE.md) admits patches for determinism, crashes, and accessors, each upstream as a pull request or issue. PlaneGCS's first patch makes the dependent-parameter thread deferred, for single-threaded workers (ARCHITECTURE.md, Deterministic kernel, 5). Recommended: the same policy for PlaneGCS, with single-threading allowed, and an upstream issue the maintainer files. **Decided (the maintainer, 2026-10-16): as recommended.**
8. **Region profiles** (after M3.6). FreeCAD can split a sketch's crossing geometry into regions and pad one (its internal faces; Fusion's profile regions, SolidWorks' Contour Select). M3.5 refuses crossing profiles as a whole-sketch profile. Recommended: region profiles as their own later step, with main's `TestSketchInternalFaces.py` as its tests, since FreeCAD 1.1.3's pipeline misses regions where three or more shapes overlap (fixed on main, `24ab301685`). **Decided (the maintainer, 2026-10-16): as recommended.**
