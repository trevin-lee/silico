# M0 – Foundations

**Goal:** prove the riskiest architectural choices work together before building on them: a Rust core talking to a worker process that calls OCCT through `cxx`, with OCCT installed reproducibly and results checked against FreeCAD.

**Exit test:** `box_fillet_through_worker_matches_freecad` (M0.8) passes, and the council approves with `/adversarial-review --milestone`.

---

### M0.1 – Workspace and lints

**Builds:** a Cargo workspace with empty crates `silico-core`, `silico-protocol`, `silico-kernel`, and `silico-cli`. `rust-toolchain.toml` pins the toolchain. Shared lints live in `[workspace.lints]`: `unsafe_code = "deny"`, which `silico-kernel` overrides at its crate root, and clippy `unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `dbg_macro`, `print_stdout`, and `print_stderr` set to deny. `clippy.toml` still allows unwrap, expect, and panic in `#[test]` functions and `#[cfg(test)]` modules. Helpers in integration-test files (`tests/*.rs`) aren't covered by that, so those files may start with `#![allow(clippy::unwrap_used, clippy::expect_used, clippy::panic)]`, and only those files. `forbid` isn't usable in the workspace table, because no crate could then override it. The gaps this leaves: a crate missing `[lints] workspace = true` is caught by the gate (M0.3); an `allow`, `expect`, `warn`, or `cfg_attr` lowering `unsafe_code` in a non-FFI crate is left to review (see M0.3, Not built). Also `rustfmt.toml`, and `[workspace.dependencies]` for shared versions.

**Tests:**
- `cargo build`, `cargo clippy --all-targets -- -D warnings`, and `cargo nextest run` all pass.
- `silico_binary_runs`: the `silico` binary starts and exits 0. It's the workspace's first real test, so `nextest` never needs `--no-tests=pass`, and the gate never uses that flag: a run that collects zero tests always fails.
- Manual check, recorded in the merge commit: adding `unsafe {}` to `silico-core` fails to compile, and adding `.unwrap()` in non-test code fails clippy.

### M0.2 – pixi environment and the deterministic OCCT build

**Builds:**
- A `pixi.toml` that pins the toolchain: clang 21.1.8, libc++ 21.1.8 (headers and runtime), cmake, and ninja. On macOS, linking uses Apple's linker, because lld 21 can't read the macOS 27 SDK.
- `third_party/occt/`: the pinned OCCT release (tag and sha256), the patch series, and a build script that fetches, verifies, patches, and builds OCCT's modeling modules with the recipe in ARCHITECTURE.md's *Deterministic kernel*. The `libm` math shim is part of this step.
- pixi tasks `occt`, `build`, `test`, `lint`, `stress`, `test-guards`, `test-cache`, and `shim-test`.
- A separate `oracle` environment that provides FreeCAD for the oracle tests. Locally on macOS, `/Applications/FreeCAD.app` is the fallback.

**As built:**
- The libm shim is the standalone crate `third_party/occt/libm-shim/`, outside the Cargo workspace because it needs `panic = "abort"` and fat LTO. It's compiled to a single object with no undefined symbols and linked into every OCCT library as a private copy (an unexported-symbols list on macOS, a version script on Linux). Its tests check every export against known values and against the platform library (1 to 4 ulps; `atanh` up to 32 because Rust's own `atanh` is a formula). In the test build the C symbols aren't exported: otherwise the test binary's `sin` replaces the platform's, and the comparison is with itself.
- `third_party/occt/build.sh` caches by a stamp over everything that affects the binaries (the inputs, the toolchain's exact package versions, the flags), with no absolute paths, so every checkout of a commit computes the same stamp. The checks in `third_party/occt/scripts/` run on every invocation, even when the build is up to date. Builds are shared between checkouts and worktrees through a cache in `~/.cache/silico/occt/v1/`; `scripts/cache.sh` describes how entries are published, used, kept, and removed under one lock. A second checkout of a commit gets OCCT in seconds instead of 3 minutes. Library search paths are rewritten to the library's own directory, and `-ffile-prefix-map` keeps build paths out of `__FILE__` strings, so an entry doesn't depend on the checkout that built it; `check-relocatable.sh` proves it.
- The recipe adds `-fmath-errno` and `-fno-builtin-<fn>` for each inexact function in `scripts/inexact-math.txt`: without them clang folds math calls with constant arguments at build time using the build machine's math library. The same list generates the canary (54 calls, double and float). A blanket `-fno-builtin` also worked but pushed every `sqrt` and `memcpy` out of line for about 2.5% speed.
- OCCT is built with `BUILD_RELEASE_DISABLE_EXCEPTIONS=OFF`, so its input checks throw instead of being compiled out; `check-exceptions.sh` proves it. The stress output was unchanged.
- The recipe costs about 6% against stock conda-forge OCCT on the stress test.
- Patches are applied with `patch --forward` and verified with `patch -R -f --dry-run`. Not `git apply`, which silently skips patches inside another repository, and not `--batch` for the check, which "assumes" a reverse patch that looks already reversed was meant forwards and so passes on unpatched source. Both traps were hit while building this step.
- `test-guards` feeds every guard input it must reject and fails if any guard lets it through: unpatched source; plain flags and `-fmath-errno` alone; a library calling the platform's `sin`; a weak import of `sin`; a static archive and an object file; an empty directory; a TKernel calling `sin`; an OCCT with its input checks compiled out; a library exporting the shim; no libraries at all; and on Linux, `feenableexcept` outside TKernel. Negative cases must fail with the expected message, not just fail. It also checks the canary covered every listed function, and on Linux that TKernel may enable traps.
- `recipe.env` exists only while the checks pass: every run removes it, checks against a fresh copy written from current paths, and publishes that copy on success. Moving the checkout, or a check that starts failing, can't leave a stale recipe behind.
- The shim's `every_export_is_tested` test fails if an export is added without a test.
- `test-cache` proves the cache's documented behavior against fake builds, with no OCCT build needed: publishing, using, pruning order and protection, broken entries, and that every command holds the lock exclusively. Each case was proven by reintroducing its bug. Writing them caught real bugs, among them `ln -s` following an existing entry into its directory and `ls` hiding the dot-named usage records.
- The oracle is FreeCAD 1.1.3 on **OCCT 7.9.3** from conda-forge, the release Silico now runs too (it ran 8.0.1 until M1.5); the local `FreeCAD.app` is FreeCAD 1.1.3 on OCCT 7.8.1. Silico's recipe still changes the last bits, so M1.8 compares geometry within tolerance and treats a case that succeeds in one and fails in the other as a finding to triage, not an automatic failure.

**Tests:**
Each named check below is a script in `third_party/occt/scripts/`, run by `build.sh` on every invocation and exercised against bad input by `test-guards`.

- On a clean checkout, `pixi run test` installs the toolchain, builds OCCT, and runs the shim tests, the guard tests, and the workspace tests.
- `occt_patches_applied` (`verify-patches.sh`): after patching, every patch in `series` reverse-applies cleanly (`patch -R --dry-run`), proving it's really in the source. A build that skipped a patch fails. This guards against `git apply` silently skipping patches inside another repository.
- `occt_no_build_time_math` (`fold-canary.sh`): a constant-argument call to every function in `inexact-math.txt` (double and float), compiled with the recipe's flags, must remain a real call.
- `occt_throws` (`check-exceptions.sh`): the built OCCT throws `Standard_Failure` on invalid input (a zero scale).
- `occt_shim_private` (`check-shim-hidden.sh`): no OCCT library exports a shim symbol.
- `occt_imports_no_platform_math` (`check-math-imports.sh`; only TKernel may import `feenableexcept`): every math function a built OCCT library imports from the system is on the exact-by-definition allowlist (`sqrt`, `floor`, `fmod`, `ldexp`, and the like). Anything else, such as `sin`, `powf`, or `__exp10`, fails. An allowlist, not a blocklist: the compiler can introduce calls nobody wrote, such as `pow(10, x)` becoming `exp10`.
- `stress_corpus_bit_identical` (`pixi run stress`, `stress.sh`): the 605-case stress test from `tests/determinism/` gives byte-identical output across 10 runs, and matches the committed reference output.
- `pixi run -e oracle freecadcmd -c "import Part; print(Part.OCC_VERSION)"` runs and prints the version it uses. The oracle needs only results within tolerance, so its OCCT version is recorded, not required to match.

### M0.3 – The local gate

**Builds:** `pixi run gate`, the check every branch must pass before it merges. It runs on the Mac, and CI (M0.9) runs the same script on the workstation.

The gate checks out the branch's **committed** tree into a fresh temporary worktree, so it can't depend on uncommitted files or local leftovers. There it runs:
- `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings`;
- `pixi run test` (workspace tests, shim tests, guard tests), including the oracle tests once they exist;
- `pixi run stress`, the cross-run determinism check;
- `cargo mutants --in-diff` against `main`;
- **forbid `unsafe` outside FFI crates:** `cargo check --workspace --all-targets` with a `RUSTC_WORKSPACE_WRAPPER` script that appends `-F unsafe_code` unless `$CARGO_PKG_NAME` is an FFI crate. A lint forbidden on the command line can't be lowered by any attribute (`allow`, `expect`, `warn`, `cfg_attr`). The wrapper applies it per crate because `RUSTFLAGS` would also hit FFI crates built as dependencies, and would replace any `rustflags` in `.cargo/config.toml`;
- **forbid panics and platform math in non-test code:** `cargo clippy --workspace --lib --bins -- -D warnings -F clippy::unwrap_used -F clippy::expect_used -F clippy::panic -F clippy::todo -F clippy::unimplemented -F clippy::dbg_macro -F clippy::print_stdout -F clippy::print_stderr -F clippy::disallowed_methods`. Test targets aren't compiled in this pass, so test files keep their exemption. Build scripts are compiled, so `build.rs` files return `Result` from `main` and report through `cargo:warning=`, never `expect`, `panic!`, or `eprintln!`;
- **cover every configuration:** the unsafe and panic passes run twice, once as above and once with `--release --all-features`, so code behind `cfg(not(debug_assertions))` or an optional feature is checked too. A source check rejects `cfg(clippy)` and `cfg(not(clippy))`, which would hide code from clippy entirely;
- a check that every member crate's `Cargo.toml` has `[lints] workspace = true`;
- `cargo deny check`, with a `deny.toml` that bans `silico-kernel` and `cxx` except as dependencies of `silico-kernel` itself (its `wrappers` setting), so OCCT can't reach an app-process crate through any dependency; the same tool checks licenses (GPL compatibility) and security advisories;
- a check that `silico-kernel` built without `test_ops` contains no `debug_` symbols, and that the production worker binary refuses every `debug_*` request.

A pre-commit hook in `.githooks/`, installed with `pixi run install-hooks`, runs fmt and clippy on every commit. `/adversarial-review` runs the gate first and stops if it fails.

**Tests (each a manual check, recorded in the merge commit):**
- The gate passes on a clean branch.
- A deliberately failing test fails the gate.
- Code that depends on an uncommitted file fails the gate, even though it builds in the working tree.
- A surviving mutant fails the gate.
- Each of `#[allow(unsafe_code)]`, `#[expect(unsafe_code)]`, `#[warn(unsafe_code)]`, and `#[cfg_attr(all(), allow(unsafe_code))]` on an `unsafe` block in `silico-core` fails the gate.
- `silico-kernel`'s own targets (its library with `unsafe`, its tests) pass the `unsafe` check.
- Each of `#[expect(clippy::unwrap_used)]`, `#[allow(clippy::restriction)]`, and `#[cfg_attr(all(), allow(clippy::panic))]` on non-test code in `silico-core` fails the gate.
- A new crate without `[lints] workspace = true` fails the gate.
- Each of these in `silico-core` fails the gate: `.unwrap()` under `#[cfg(not(debug_assertions))]`; `.unwrap()` under an optional feature; `.unwrap()` under `#[cfg(not(clippy))]`; `#[allow(clippy::disallowed_methods)]` on a function calling `x.exp()`.
- `platform_math_banned`: calling `x.sin()`, `f64::powi(x, 2)`, or `.map(f64::tan)` in `silico-core` fails the gate. This also catches a mistyped path in `clippy.toml`, which clippy accepts silently.
- Long tests (the stress and oracle suites) have their own longer timeout in `.config/nextest.toml`, so the 2-minute hang limit applies only to ordinary tests.

**As built** (deliberately leaner than planned: checks were added when they had code to protect, and only with standard tools):
- `pixi run gate` (`tests/gate.sh`) checks out HEAD into a worktree in the user cache (one per checkout, reused between runs and cleaned of everything untracked except `target/` and `.pixi/`; outside the repository, because Cargo would take the outer checkout's workspace for the gate's). There it checks, in order: every crate has `[lints] workspace = true`; `cargo deny check bans licenses sources` (`deny.toml`: only `silico-kernel` may depend on `silico-kernel`, `cxx`, or `cxx-build`, and only `cxx` on `link-cplusplus`, with optional features included; licenses compatible with GPL-3.0-or-later, Silico's own crates included; crates.io only); `pixi run lint`; `pixi run test` (which includes the guard, cache, shim, and oracle tests); and one stress run.
- Proven by hand: it passes a clean branch, and fails on a failing test, on code that depends on an uncommitted file (it builds in the working tree), on a crate without the workspace lints, and (through cargo-deny) on a crate that depends on `silico-kernel` or `cxx`.
- `pixi run lint` now depends on `occt`, since clippy compiles the kernel's bridge.
- Two gate runs from one checkout can't overlap: a run holds a lock on its worktree (Perl's `flock`, as the OCCT cache does) and says so while it waits. Each checkout's gate worktree stays in `~/.cache/silico/gate/` (several GB with its build caches); delete the directory to reclaim the space.
- Not built, and why: the `RUSTC_WORKSPACE_WRAPPER` that forbids `unsafe` per crate (so an `allow` can lower the workspace's `unsafe_code` and `disallowed_methods` lints, and review must catch it), the `cfg(clippy)` and `--all-features` passes, the check that `silico-kernel` without `test_ops` has no `debug_` symbols and that the production worker refuses debug operations (the latter is a test), cargo-deny's security advisories (which need the network), the pre-commit hook, and `/adversarial-review` running the gate first. They guard against mistakes nobody has made yet; the workspace lints and review cover them for now (the maintainer's call, 2026-10-08). Mutation testing is run per change by hand (`cargo mutants`), not in the gate, where it would take many minutes. CI (M0.9) will run the same script.

### M0.4 – The cxx bridge

**Builds:** in `silico-kernel`, a C++ shim and a `cxx` bridge. `build.rs` builds the bridge with the deterministic recipe from `target/occt/recipe.env`: its compiler (`SILICO_CXX`) and flags. `build.rs` also emits `cargo:rustc-link-arg=<the shim object>`, so every executable of `silico-kernel` (the worker, test binaries, benches, examples) links one copy of the shim, which covers the bridge's math and Rust's own. It never relies on OCCT's copies, which are private. Only `silico-kernel` links the bridge: other crates reach OCCT through the worker process (invariant 1), and no other crate depends on `silico-kernel`'s library. `check-math-imports.sh` runs on every built `silico-kernel` executable, including the test binaries. Two functions: `make_box(dx, dy, dz) -> Result<UniquePtr<Shape>>` and `volume(&Shape) -> f64`. Every shim function catches `Standard_Failure` and `std::exception` and turns them into Rust `Err`, so no exception ever crosses the bridge.

**Tests:**
- `box_volume_is_exact`: a 10 × 20 × 30 box has volume 6000, within relative 1e-9 (analytic).
- `box_zero_dimension_is_err`: `make_box(0, 20, 30)` returns `Err` and does not abort the process.
- `box_negative_and_nan_are_err`: negative and `NaN` dimensions return `Err`.
- `exception_becomes_err` (as built, `every_exception_becomes_err`): a test-only shim function that throws `Standard_Failure` returns `Err` containing OCCT's message.

**As built:**
- The Rust API is `make_box(dx, dy, dz) -> Result<Shape, KernelError>`, `mass_properties(&Shape) -> Result<MassProperties, KernelError>` (volume and center of mass from one integration; the center lets a test tell a box's placement and orientation, which volume alone can't), and `volume(&Shape)` over it; `Shape` wraps the `UniquePtr`. Every function returns a `Result` because any OCCT call can throw. `KernelError` holds OCCT's message and stays inside the worker: the worker reports it as a protocol `Failure` (M0.6), and the core maps that to its structured `Error` (`kernel_failed`, OCCT's message as the cause), so `silico-kernel` never depends on `silico-core`. Lengths are in the document's unit (mm), as plain `f64` until core has a length type.
- OCCT's `BRepPrimAPI_MakeBox` (8.0.1 and 7.9.3 alike) accepts a negative size and builds the same box mirrored to the other side of the origin. Silico treats box sizes as lengths, as FreeCAD's Part Box does, so the Rust side rejects negative and non-finite sizes (OCCT also lets `NaN` through), naming the size at fault. Whether a negative size means anything is a feature rule that core will own; the bridge's check keeps it from ever building something other than what was asked, and must stay consistent with core's. Zero and sizes at or below OCCT's 1e-7 tolerance, which OCCT rejects with a bare `Standard_DomainError`, are refused the same way, naming the size.
- In OCCT 7.9, `Standard_Failure` isn't a `std::exception` (OCCT 8 made it one, with `ExceptionType()`): the bridge's `rust::behavior::trycatch` (in `cpp/bridge.h`) names its type with `DynamicType()->Name()` and reports `"<type>: <message>"`, so `Standard_DomainError` and `StdFail_NotDone` stay distinguishable, and also catches anything that isn't a `std::exception`.
- `.cargo/config.toml` forces (`force = true`) every C++ compile in the build, including the `cxx` crate's own runtime, onto the pinned clang and libc++. Otherwise the `cxx` runtime would be built by the system compiler, against libstdc++ on Linux, putting two C++ standard libraries in one process. The cc crate appends flags from the environment after the recipe's, so a shell's `CXXFLAGS=-ffp-contract=fast` would have cancelled `-ffp-contract=off`: forcing the config's values stops that, and `build.rs` fails on any other C++ variable cc reads (`CXXFLAGS_<target>`, `TARGET_CXXFLAGS`, and the like). The rule is in `cxx_env.rs`, which `build.rs` and `tests/cxx_env.rs` share; the end-to-end effect (only `-ffp-contract=off` reaches the bridge under a hostile shell, and a per-target variable stops the build) was verified by hand on macOS and Linux.
- `build.rs` finds libc++ beside the recipe's compiler and adds run-time search paths for it and for OCCT (through the checkout's `target/occt/install` link), so test binaries run without any environment set up.
- Each `silico-kernel` test binary runs `check-math-imports.sh` on itself (`tests/common/imports.rs`), after calling `sin`, so the check fails if the shim's link argument is ever dropped (verified by removing it).
- Another crate depending on `silico-kernel` (which would put OCCT, without the libm shim, in that crate's process) is caught by the gate's `cargo deny` check (M0.3), a standard tool. An earlier hand-written dependency-graph walk was dropped: every review round found another way around its list of package names (the maintainer's call, 2026-10-08). C++ a third-party crate compiles itself, through `cc`, isn't caught; review covers it.
- The test-only throws (`Standard_Failure`, `std::runtime_error`, and a non-exception `int`) sit behind the `test_ops` feature, which only this crate's own tests enable, through a dev-dependency on itself. A build without it contains none of them (checked by hand; no automated check). Cargo turns the feature on for every target of the package whenever a test target is built, so a binary must never rely on it being off: see M0.7.
- Extra tests: `box_spans_origin_to_its_size` (center (5, 10, 15)), `box_sizes_near_the_limits_are_accepted` (2e-7 to 1e6), `box_huge_or_subnormal_sizes_are_err`, `errors_leave_the_bridge_usable` (100 rounds of failures, then a correct box), and every branch of the exception conversion, including an empty message and `Display`. Each was proven by a mutant that the earlier tests missed: swapped axes, a centered box, size cutoffs, a missing catch branch, the wrong size named.

### M0.5 – Error type and tracing

**Builds:** the structured error type in `silico-core`. It carries a stable `code` enum, plus optional `feature`, `element`, `cause`, `suggestion`, and `candidates`. It implements `Display` for humans and `serde::Serialize` for MCP. `tracing` is initialized in `silico-cli`, with JSON output available.

**Tests:**
- `error_json_shape`: snapshot test of the serialized error. This file is the contract with agents, and changing it is deliberate.
- `error_codes_are_stable`: snapshot of every code and its string form, so a code can't be renamed or renumbered silently.
- `display_names_feature_and_element`: the human-readable message includes the feature, the element, and the suggestion.

**As built:**
- `silico_core::Error` and `ErrorCode`. The codes so far are `invalid_input`, `kernel_failed`, `worker_crashed`, `worker_timeout`, `protocol_error`, `internal`, and `invalid_result` (an operation's result was refused as invalid); new ones are appended, never renamed or removed. The JSON contract is in `crates/silico-core/tests/contract/`: every field is always present (`null` when absent, `[]` for no candidates), so agents parse one shape. `Display` reads `code: message (feature F, element E): cause. Suggestion: S. Candidates: A, B.`, leaving out what's absent.
- `silico` logs through `tracing` to stderr only, so stdout stays free for command output. `SILICO_LOG` is the filter (default `warn`, also when empty; an invalid or non-UTF-8 one is reported and ignored), and `SILICO_LOG_FORMAT` is `text` (default) or `json`, one JSON object per line; anything else is reported and ignored. Colour only when stderr is a terminal.
- The codes, `ErrorCode::ALL`, and the string forms come from one macro, and serialization goes through `as_str`, so a code can't be missing from the snapshot or serialize differently from its string. `tests/contract/` is protected (CLAUDE.md).
- Extra tests: the error without optional fields, `Display` for each combination, logging defaults, JSON lines, and an invalid filter. `cargo mutants` catches every viable mutant in both crates.

### M0.6 – Protocol and framing

**Builds:** in `silico-protocol`, the types `Request { id, generation, op }` and `Response { id, result }`. Messages are length-prefixed frames, encoded with serde and `postcard`, with a maximum frame size. The decoder works incrementally over any `Read`.

**Tests:**
- `roundtrip_every_op`: every request and response type survives encode → decode unchanged.
- `decoder_never_panics` (proptest, at least 10,000 cases): arbitrary bytes produce `Ok` or a decode error, never a panic.
- `truncated_frame_is_error`: cutting a valid frame at every byte offset gives a clean error.
- `oversized_frame_rejected`: a length prefix above the maximum is rejected before any allocation.
- A `cargo fuzz` target for the decoder, run for at least 5 minutes before merging.

**As built:**
- `Op`: `MakeBox`, `MassProperties { shape: Blob }`, and the test operations (`DebugSleep`, `DebugAbort`, `DebugSegfault`, `DebugGarbage`), which only the test worker answers. `Response.result` is `Result<Reply, Failure>`, where `Reply` is `Shape { brep }`, `MassProperties { volume, center }`, or `Done`, and `Failure` is a kind (`InvalidInput`, `KernelFailed`, `UnknownOp`) plus the worker's message. The core turns a `Failure` into its structured `Error`; the protocol doesn't depend on `silico-core`.
- `Blob` is an enum with one variant, `Inline(bytes)`, so a shared-memory variant can be added later without changing any message that carries one. Its `Debug` prints the length, not the bytes.
- A frame is a 4-byte little-endian length, then the `postcard` payload; the maximum is 512 MiB, room for a large B-rep or mesh. The reader rejects a length over the maximum from the header alone, and grows its buffer only as bytes arrive, so a peer lying about the length can't make it allocate. A payload with bytes left after the message is an error, and so is a stream that ends mid-frame; a clean end between frames is `None`. Interrupted reads are retried.
- The decoded message owns its bytes: a `Blob` is copied once out of the frame buffer. That's a memory copy against a socket transfer, and the M0.7 benchmark measures the whole path.
- Tests: every operation and reply round-trips (each variant maps to its own index and every index must appear, so a new variant without a test case fails), the exact byte layout of a frame, truncation at every byte, oversized and lying lengths, trailing bytes, a frame of the wrong message type, interrupted and failing readers, and the error messages. Proptest feeds 10,000 random streams (their first length clamped under the maximum, so they reach the decoder) and 10,000 random payloads behind valid headers to the decoder, and round-trips random requests. `cargo mutants` catches every viable mutant.
- `tests/allocation.rs` measures allocation with a counting allocator (`stats_alloc`): a header claiming 512 MiB with 10 bytes behind it allocates under 64 KiB, and an oversized length allocates nothing for the payload. Time and memory can't show this on macOS, where large allocations are lazy.
- `crates/silico-protocol/fuzz/` (its own workspace with its own lockfile; run through pixi, which provides the pinned C++ toolchain `.cargo/config.toml` points at: `pixi run cargo +nightly fuzz run decode`) fuzzed the decoder for 5 minutes: 50.8 million inputs, no crash, hang, or out-of-memory.

### M0.7 – Worker process and client

**Builds:** the `silico-kernel-worker` binary, which talks to the core over a Unix socket pair: the core creates it with `socketpair()` at spawn and the worker inherits its end as file descriptor 3. Requests and responses are frames on that one bidirectional socket; stdout is unused and stderr carries the worker's logs into `tracing`. A socket pair costs the same as pipes, and can later pass a shared-memory descriptor for large blobs (see `Blob`). Shapes cross as OCCT binary B-rep, so workers keep no state: any worker can run any request, and a crashed one is just replaced. At startup it disables OCCT's floating-point traps (`OSD::SetFloatingSignal(false)`) and refuses to run if any trap is enabled, and it checks again after every request. Like every `silico-kernel` executable, it links the libm shim object through `build.rs`, and `check-math-imports.sh` runs on it. In `silico-core`, a client that spawns one worker, sends a request, and waits with a timeout. When a worker crashes or times out, the client kills it, reaps the process, and returns a structured `WorkerCrashed` or `WorkerTimeout` error. The client is plain threads and channels, no async runtime: each worker has a reader thread, and timeouts are channel receive timeouts. A separate test worker binary, `silico-kernel-test-worker` (`required-features = ["test_ops"]`; an underscore, because cxx-build matches bridge `cfg(feature)`s against Cargo's `CARGO_FEATURE_*` names without mapping `-` to `_`), adds operations for testing: `debug_sleep`, `debug_abort`, `debug_segfault`, and `debug_garbage` (writes invalid bytes). The production worker's source never dispatches them, because Cargo turns `test_ops` on for every target of the package whenever tests are built, so a production binary built alongside the tests would otherwise answer them.

**Tests:**
- `box_volume_through_worker`: `make_box` then `volume` through the worker returns 6000.
- `segfault_becomes_error`: `debug_segfault` gives `WorkerCrashed`, and the test process keeps running.
- `abort_becomes_error`: same, for `debug_abort`.
- `hang_times_out`: `debug_sleep(60s)` with a 1 s timeout gives `WorkerTimeout` within 2 s, and the worker's process ID no longer exists.
- `garbage_reply_is_error`: `debug_garbage` gives a protocol error and the worker is killed.
- `production_worker_refuses_debug_ops`: the production worker answers every `debug_*` request with a structured "unknown operation" error, even when built in the same `cargo test` run as the test worker.
- `fp_traps_off`: the worker reports no floating-point traps enabled on startup, a worker started with traps forced on refuses to run, and a request that turns traps on fails with a structured error.
- `worker_imports_no_platform_math`: `check-math-imports.sh` passes on the built worker executable, and fails on a test build that calls the platform's `sin`.
- `no_zombies`: after 100 crash and timeout cycles, the test process has no child processes left.
- `ipc_budget` (a benchmark, results recorded under As built): a small request's round trip through the worker takes under 50 µs, and a 10 MB `Blob` moves at over 1 GB/s. Missing either, or a later measurement of sketch drags (M3), is the trigger to give `Blob` a shared-memory variant.

**As built:**
- `silico_core::worker::Worker` starts a worker with `UnixStream::pair()`; the worker's end goes to it as descriptor 3 (through `command-fds`, so the core has no `unsafe`), named by `SILICO_WORKER_FD`. A worker started any other way exits with code 2. Both ends ask for 4 MiB socket buffers: macOS defaults to 8 KiB, which made a 10 MB blob take thousands of system calls (1.0 GB/s, against 3.0 GB/s with the larger buffers).
- `Worker::call(generation, op, timeout)` returns the reply or a structured `Error`. A worker failure maps to `invalid_input` (the bridge refused the values), `kernel_failed` (OCCT refused or failed; OCCT's message is the cause), `invalid_result` (OCCT performed it, but the result was refused as invalid), or `internal`. Every kernel failure carries a suggestion. A closed socket is `worker_crashed`, with how the process ended (exit code, or signal with its name) and the worker's last 20 stderr lines as the cause; a timeout is `worker_timeout`; an unreadable or out-of-turn reply is `protocol_error`. In each of those three cases the worker is killed and reaped, and later calls on it fail at once.
- Tracing follows work across the boundary: every request carries a `trace` ID (unique in the core process), `Worker::call` opens a `worker_call` span with it, and the worker records it on its request span. The worker logs JSON lines to stderr; the core re-emits each at its own level (target `silico::worker`, with `pid` and `trace`), so a worker's errors aren't hidden at the default `warn`. Lines are read as bytes (text that isn't UTF-8 can't stop the reading) and cut at 8 KiB; the last 20, as `LEVEL message`, go into crash reports, after the log pipe has closed.
- `timeout` covers sending as well as waiting: a request a worker won't read times out instead of blocking. A request over the frame limit is `invalid_input` and leaves the worker running. A reply whose id or generation doesn't match the request is `protocol_error`. Replies queue one deep, a failed spawn leaves no process behind, and a call on a stopped worker is `worker_crashed` with "start a new kernel worker" as the suggestion. Signals are named by the platform's own numbers (`libc`).
- Shapes cross as OCCT binary B-rep (`BinTools`) plus a CRC-32, so workers keep no state; a test builds a box in one worker and measures it in another. OCCT reads many corrupted B-reps as a different shape without complaint (a review found single-byte flips giving volume 4000 for a 6000 box), so `from_brep` checks the CRC before OCCT sees the bytes; every single-byte flip of a box's B-rep is refused. The cache (M2) stores B-rep in the same form, with its validity (see M0.8). Mass properties that aren't finite are refused too. The B-rep crosses the bridge as one `std::string` (copying byte by byte was 16 times slower) and is read back through a seekable stream over the bytes, without copying them. `Op::Echo` sends a blob straight back: a health check, and what the benchmark measures.
- Floating-point traps: the worker switches them off through OCCT at startup and refuses to run if any is still on, and checks after every request; a request that leaves them on fails as `internal` and they're switched off again. The check reads glibc's `fegetexcept` on Linux and the FPCR trap-enable bits on Apple silicon. Apple silicon ignores those bits, so traps can't be switched on there at all: the "traps on" tests run on Linux, and on macOS a test confirms the request leaves them off. Forcing traps on at startup can't be tested end to end (startup switches them off first), so the startup check is tested in-process.
- The test worker (`silico-kernel-test-worker`) answers the debug operations; the production worker answers them with `internal` ("a test operation"), tested. The segfault hook restores the default SIGSEGV action before raising it, because Rust's own SIGSEGV handler (for stack overflows) returns from a raised signal, where a real fault would fault again and die.
- `ipc_budget` is `cargo bench -p silico-kernel --bench ipc`, which fails if over budget. It also records the real shape path, a box built and measured through the worker: 148 µs median on the Mac, mostly OCCT. Release builds: on the Mac (M-series), small round trip median 11 µs (p99 21 µs) and 10 MB echo 3.0 GB/s counting both directions; on Linux (x86-64 VM), 4.6 µs (p99 16 µs) and 4.0 GB/s. Within budget, so `Blob` stays inline.
- `no_zombies` runs 100 segfault, abort, and timeout cycles plus 10 idle workers dropped, then finds no child processes left.
- Mutation testing of both worker modules against every test in the workspace: the survivors are the socket buffer size (performance only; the benchmark covers it), a `<` that could be `<=` in the exit wait, a detail of a log message, and the trap check on macOS (which can't switch traps on; Linux's test catches it). Later review fixes were each checked by reverting them: the log-thread wait (a stand-in worker whose child writes the last line 300 ms after it exits), the generation and id checks, the trace and level of forwarded logs, the checksum, the send timeout, and the size check. The trap decision is also a pure function, `check_fp_trap_mask`, tested on every platform. The rest are caught, including by tests added for them: a reply out of turn (`DebugReplyOutOfTurn`, which first sends a reply with the previous request's id, or with this request's id and another generation), the crash report keeping exactly the last 20 lines, a descriptor that isn't a socket, every named signal, and each worker being alive before it's checked gone.

### M0.8 – Fillet and the FreeCAD oracle

**Builds:** a shim function `fillet(shape, edge_indices, radius)`. Edges are indexed using OCCT's `TopExp::MapShapes` order. Also a shape summary with volume, area, face/edge/vertex counts, and validity from `BRepCheck_Analyzer`. And a minimal oracle helper: it runs a FreeCAD Python script with `freecadcmd` and parses the JSON it prints.

**Tests:**
- `box_fillet_analytic`: a 10 × 20 × 30 box with one edge of length 30 filleted at r = 2 gives:
  - volume 5974.24778 (6000 − (4 − π)·30), within relative 1e-6;
  - area 2172.53097 (2200 − 120 + 30π − 2(4 − π)), within relative 1e-6;
  - 7 faces, 15 edges, 10 vertices;
  - a valid shape.
- `box_fillet_through_worker_matches_freecad` (**the M0 exit test**): the same operation through the worker and through FreeCAD gives the same volume and area within relative 1e-9, the same topology counts, and both shapes are valid.
- `fillet_too_large_is_structured_error`: r = 11 on an edge whose adjacent face is 10 wide returns a `FilletFailed` error naming the edge. If FreeCAD succeeds on this input, record it as a spec question instead of asserting.

**As built:**
- Bridge: `fillet(shape, edges, radius)`, `summarize(shape)` (volume, area, center, distinct face, edge, and vertex counts, and `BRepCheck_Analyzer` validity), and `edge_count`. Edges are numbered from 1 in `TopExp::MapShapes` order, which is FreeCAD's `Edge1`, `Edge2`, and so on, so the two can be compared edge for edge. The Rust side refuses a radius that isn't a positive, finite length, an empty edge list, an edge number out of range (naming the range), and a repeated edge, before OCCT sees them.
- Protocol: `Op::Fillet { shape, edges, radius }` and `Op::Summarize { shape }` (which replaces `MassProperties`), replying `Reply::Summary(ShapeSummary)`. A `Failure` can name the element at fault; the worker names the edge when a single-edge fillet fails, and the core puts it in the error's `element`. So the plan's "`FilletFailed` error naming the edge" is `kernel_failed` with message `Fillet failed`, element `Edge1`, and OCCT's message as the cause: a new code wasn't needed. The element is named only when an edge is at fault: an edge out of range or repeated, or the single edge of a failed fillet; never for a bad radius, and never guessed among several edges.
- Shapes cross the boundary as `ShapeData`, in requests and in `Reply::Shape`: the B-rep, and whether `BRepCheck_Analyzer` finds the whole shape valid, if known. A worker checks each shape it makes and says (`ShapeData::checked`); the core passes the shape back unchanged, and workers take its word, so the result guard never rechecks its input and `Summarize` reports it without checking again: one whole-shape check per operation, on its result. A shape no worker has vouched for (a file, an import) is `ShapeData::unchecked`, and each worker given it checks it; the cache (M2) will store each shape's validity with its B-rep, under the same checksum, and rebuild `ShapeData::checked` from it, so a `checked` is only ever a worker's word, live or replayed. The fields are private, so a claim of validity can't be made by accident. In a worker, `silico_kernel::Shape` keeps its validity once known (`is_valid`, `with_validity`).
- The oracle helper (`crates/silico-kernel/tests/common/oracle.rs`) runs a FreeCAD script with `freecadcmd` from the pixi `oracle` environment (FreeCAD 1.1.3 on OCCT 7.9.3) and parses the JSON it prints. A missing oracle fails the test rather than skipping it; `pixi run test` installs the environment first (`install-oracle`). FreeCAD 1.1 returns a fillet inside a compound, so the oracle reads the center from its one solid.
- **The M0 exit test** (`box_fillet_through_worker_matches_freecad`) runs 14 cases through the worker and through FreeCAD: single edges, four parallel edges, two edges meeting at a corner, all 12 edges, a short edge, radii up to the limit, and radii of 1e-8, 1e-12, and 1e300. The 8 that succeed agree on volume, area (both within relative 1e-9), center, topology counts, and validity; the single r = 2 fillet's volume is bit-identical to FreeCAD's, 5974.247779607694. The 4 that fail in both fail as `kernel_failed`. For the 2 where OCCT returns an invalid solid (every edge at r = 5.01 and 5.5), FreeCAD 1.1 returns it and Silico refuses it. The refusal is FreeCAD's original check (`BRepAlgo::IsValid` on the faces the fillet changed), with the whole result checked too when the input is valid, decided in Rust, and reported with its own code, `invalid_result`; see [docs/ports/fillet.md](../ports/fillet.md).
- **Invalid results are refused.** OCCT reports some fillets done whose result isn't a valid solid (volume larger than the box). FreeCAD refused those from 2016 and lost the refusal in 2024; Silico refuses them: the faces the fillet changed must pass FreeCAD's 2016 check (`BRepAlgo::IsValid`), and when the input is valid the whole result must pass `BRepCheck_Analyzer` too. The decision is made in Rust, and FreeCAD's 2017 tolerance repair isn't ported (it repaired nothing). The guard history, where each guard lives, and which FreeCAD tests are ported are in [docs/ports/fillet.md](../ports/fillet.md). Two FreeCAD fillet tests are ported now (cube to sphere, and every edge of a unit cube at r = 0.05, whose area 5.739646 is also analytic).
- Checked by breaking it: edge numbers off by one, the radius off by 1e-6 (caught by the analytic test alone, at relative 1e-12), validity always true (`test_ops::open_box`, a box with a face missing, must summarize as invalid), the validity refusal removed, the failing edge left unnamed, and the first of several edges blamed. Each fails a test. A fillet is also byte-for-byte deterministic across workers and repeats.
- Found along the way: OCCT aborts the process on some corrupted B-reps even when their checksum is made to match, which is what running it in a worker is for: in a worker, that's a `worker_crashed` error, not a crashed app.

### Debug viewer (added during M0)

**Builds:** a way to see what the kernel builds before the app exists (ROADMAP.md: "tests and agents log geometry to Rerun as a debug viewer").
- `Op::Tessellate { shape, deflection }` replies `Reply::Mesh`: triangles wound outward, triangles per face, and a polyline along each edge, edges numbered as `Op::Fillet` numbers them. Meshing is OCCT's `BRepMesh_IncrementalMesh`, single-threaded so a shape always gives the same mesh, run on a copy of the shape: meshing changes the shape it meshes (OCCT stores the mesh on it and updates edge flags, which changes its B-rep bytes), and B-reps are written without meshes. A deflection below 1e-4 of the shape's diagonal is refused (each tenth of the deflection costs about ten times the triangles and seventy times the time: 1e-5 on a filleted box took 48 s), and a face that fails to mesh is an error rather than a hole. The bridge returns the mesh as an opaque C++ object whose arrays Rust copies once each, into `silico_protocol::Mesh`, which `Mesh::validate` checks before anything indexes it.
- `silico-view` (a binary crate, no C++) builds a box, the box with Edge1 filleted at r = 2, and the box with every edge filleted at r = 1, through a real worker, and logs each to Rerun: shaded faces, every edge labelled `Edge1`, `Edge2`, ..., and a summary (volume, area, topology, validity). `pixi run view` runs it with the Rerun viewer pinned in the pixi `viewer` environment (`rerun-sdk` 0.38.1, matching the `rerun` crate, logging SDK only). `--save <file.rrd>` writes a recording instead.

**Tests:**
- `a_box_mesh_is_closed_and_faces_outward`: the box mesh's enclosed volume (divergence theorem, about a point inside the box) is 6000 and its area 2200, both within relative 1e-12 (flat faces mesh exactly). About an interior point every outward triangle adds volume, so a missing or flipped one changes the result; about the origin, the faces on planes through it would add nothing either way (a review found that version couldn't fail).
- `edges_are_numbered_as_the_fillet_numbers_them`: Edge1's polyline runs between (0, 0, 30) and (0, 0, 0), FreeCAD's Edge1.
- `a_filleted_box_mesh_approximates_the_solid`: the mesh of the r = 2 fillet encloses slightly less than the analytic volume, by no more than the deflection allows.
- `a_mesh_is_the_same_every_time` (two separately built shapes; OCCT keeps a shape's mesh, so meshing one twice would prove nothing), and a bad deflection is `invalid_input`.
- `meshing_leaves_the_shape_as_it_was`: a shape's B-rep, a later fillet of it, and a coarse mesh after a fine one are all as if it had never been meshed. A deflection too fine for the shape is refused.
- Through the worker, a mesh equals one made in-process, and a bad deflection or corrupted B-rep is `invalid_input`. `Mesh::validate` rejects an index past the vertices, per-face counts that don't add up, and coordinates that aren't finite.
- `silico-view` saves a recording end to end through a real worker; its edge labels are tested in a pure function (Edge1 on the right polyline, degenerate edges skipped); a path it can't write or a viewer it can't start is `invalid_input`, and `--help` prints usage.

**Notes:** The Rerun viewer collects anonymous usage analytics by default; `rerun analytics disable` turns them off (the `rerun` crate is built without its analytics feature). One of Rerun's dependencies (`webpki-roots`) is licensed CDLA-Permissive-2.0, allowed in `deny.toml`, and one (`paste`) carries an "unmaintained" advisory, recorded as accepted there. The `rerun` crate adds about 470 packages to the workspace build.

### After the milestone review

The sections above describe each step as it was built. The milestone review and the cleanup after it changed some of what they name:

- The kernel's `mass_properties` and `volume` are gone: `summarize` is the one way to measure a shape, and returns the protocol's `ShapeSummary` (the C++ side returns `Measures`, without validity, which Rust adds from the shape's own check).
- The test operations are one variant, `Op::Debug(DebugOp)`, so the production worker refuses them in one arm and a new one touches only `DebugOp` and the test worker. `ReplyOutOfTurn` takes `OutOfTurn::WrongId` or `WrongGeneration` instead of a bool.
- `Failure::new(kind, message)` builds a failure with no element or suggestion.
- App-side logging (`SILICO_LOG`, `SILICO_LOG_FORMAT`) is `silico_core::logging::init`, used by the CLI and `silico-view`; workers keep their own JSON logging, with the same default for an empty or unusable `SILICO_LOG`.
- `tests/determinism/probe.cpp` and `compare.py`, superseded by the stress test, are removed (in git history).

### M0.9 – CI on the workstation

**Lands whenever the maintainer's runner is ready. It doesn't block the M0 exit test.**

**Builds:** GitHub Actions on a private GitHub repository. Jobs run only on the maintainer's self-hosted runner: the Ryzen 9950X3D k3s workstation, x86-64 Linux, using Actions Runner Controller (ARC).
- Every job's `runs-on` targets the self-hosted runner's labels and never a GitHub-hosted runner. If the workstation is offline, jobs queue instead of spending paid minutes. GitHub fails a job that has been queued for more than 24 hours, so after a long outage those runs need a re-run.
- The repository stays private while CI caches persist between jobs. If it ever goes public, fork pull requests must require approval before running, because they could poison the shared caches or run code on the workstation.
- Runner pods are ephemeral, and persistent volumes cache pixi packages, the cargo registry, and compiled output (sccache).
- On every push, the workflow runs `pixi run gate`, the same script as the local gate, plus the jobs too heavy for the laptop: full mutation testing and the oracle suite.
- Nightly, it runs long fuzzing and the generated oracle cases.

**Needs first:** the private GitHub repository and the remote. The maintainer creates these, or approves creating them.

**Tests:**
- A push to a branch triggers the gate, and its status shows on the commit.
- A deliberately failing test fails the run.
- No workflow job can select a GitHub-hosted runner. A check in the gate rejects any `runs-on` value without the self-hosted labels, and a workflow with `runs-on: ubuntu-latest` fails the gate (manual check).
- `cross_platform_determinism`: the stress corpus, the golden corpus, and every oracle case are bit-identical between the Mac and the workstation: shapes, names, summaries, and saved documents. Any difference fails the run and is treated as a bug.

**As built (2026-10-11, partly):**
- The repository is `trevin-lee/silico`, private. The runner isn't on the k3s workstation: it's the maintainer's existing CI VM on the Proxmox host (VM 120 `ci-runner`, Debian 13, x86-64, 16 cores, internet-only network). That VM's `ci-runner@silico-1` service mints a single-use runner for this repository for each job. The token stays with root, and jobs run as an unprivileged user with rootless Docker.
- `.github/workflows/gate.yml` runs `pixi run gate` on every pull request and push to main. `.github/workflows/oracle-sweep.yml` runs 500 generated oracle cases nightly, with the run number as the seed. Both select `[self-hosted, linux, x64, pve]`, never a GitHub-hosted runner. `.github/tools.sh` installs rustup, pixi, and cargo-nextest into the runner's home once. That home keeps the OCCT build cache, pixi's packages, and the gate's worktree with its `target/` between jobs, so a gate run takes about a minute.
- The workspace is wiped before every job, so the gate now starts its cached worktree again when the checkout it belonged to is gone, keeping the build caches. CI runs nextest's `ci` profile, which runs every test rather than stopping at the first failure.
- The first Linux runs needed `lsof` from pixi for the pool's descriptor tests. They also needed the mass-crash test to kill any worker its crash requests missed: the pool can hand a crash to a slot it has already replaced. SIGKILL is used, since OCCT catches a SIGSEGV sent from outside on Linux.
- Cross-platform determinism holds for the stress corpus: on Linux it matches the reference recorded on the Mac, byte for byte (605 cases). The golden corpus doesn't exist yet. Comparing oracle outcomes between the two machines, mutation testing and fuzzing in CI, and the gate's check of `runs-on` labels aren't built yet.
