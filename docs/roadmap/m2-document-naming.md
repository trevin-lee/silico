# M2 – Document and naming

**Status: outline.** Detail these steps once the two study notes below are written. The study shapes the steps, especially M2.7 and M2.8.

**Goal:** the JSON timeline becomes a working parametric model. It parses, validates, recomputes through the worker pool, caches per feature, checks fingerprints, and names topology stably.

**Exit tests:** golden models save and rebuild byte-identically on every platform, the ported FreeCAD naming tests pass, references survive upstream edits or fail loudly, and the council approves with `/adversarial-review --milestone`.

## As built

### M2.0 – Refusals as data

M2.0 is built in parts, each reviewed on its own:
- **The error contract** (done). The maintainer chose the shape: `elements`, a list of every sub-element at fault, replaces `element` (the first hundred where there are more, with how many in `elements_total`, added for unmeshed faces); `parameter` names the parameter at fault as a dotted name: the operation's field, and the part of it at fault where it has parts (`radius`, `offset.x`, a chamfer's `size.angle`, an extrusion's `profile`); and `resource_exhausted`, appended to the codes, is a shortage of files, processes, memory, or buffers, which `internal` (a bug in Silico) had reported. Every value the request constructors check is refused naming its parameter (a request too large to send names none).
- **Refusals from the worker as data** (done). The worker sends a `Failure` of a `Refusal` (silico-protocol, `refusal.rs`): why, as data (every element at fault as an `ElementRef`, the parameter at fault, the values that matter, an enum for each kind of reason), and OCCT's own words as its cause; no element names and no sentences. The core names the elements (as FreeCAD does, `Edge3`, until a document's names arrive) and has the refusal described with those names (`Refusal::describe`, which writes the message and the suggestion from the data, beside the type, so the core and the in-process kernel say the same thing). A refusal of several edges names every one (it named the first). Every refusal of a value names its parameter (`edges`, `deflection`, `profile`, a boolean's `base` or `tool`), and the core and the worker build those names in one place (`InvalidParameter::name`). The elements a refusal names are each of the operation's one input shape; an edge the shape doesn't have, and a profile's merged corners, aren't the shape's elements, so those refusals name their parameter (`edges`, `profile`) and the numbers. The core checks a refusal against the request it answers before describing it (the edges it names are among those the request lists, each once, in order), so a broken worker's refusal can't cost more than the request did, and one that doesn't fit is a protocol error. Two values still travel as text: an invalid parameter's message (the protocol's own check, which the core runs first, so a worker refusing one is a version mismatch) and a test worker's internal failures.
- **Unmeshed faces as data** (done). A mesh says whether the shape is valid when a face has no triangles (`Mesh::valid`, present exactly then, which `Mesh::validate` checks), and the worker no longer refuses: the core decides, leaving such faces out of a valid shape's mesh and refusing one that isn't valid (`Mesh::refusal`, `Refusal::FacesUnmeshed`): it names the first hundred unmeshed faces as elements and the first eight in its words, and counts them all (the error's `elements_total`, which the maintainer added to the contract: how many elements are at fault, more than `elements` lists only when there are too many to name), so a mesh of a million empty faces costs no more to refuse than to read. Unmeshed faces are those with no triangles, from the mesh's own counts on both sides; a worker never sends this refusal, and one that does is a protocol error. The decision is a step of its own after the reply is read (`KernelRequest`'s `decide`), so the core's refusal leaves the worker running, where a reply it can't trust stops it.
- **A multi-edge fillet's or chamfer's failing edges** (done), as OCCT reports them. The maintainer chose this over trying each edge alone across the pool (docs/ports/fillet.md has the cases): when OCCT can't build a fillet, the worker names, as the elements at fault (`Refusal::EdgesFailed`), the given edges in the contours OCCT reports it couldn't build with an error status (`NbFaultyContours`, `StripeStatus`) and in those reaching a corner it couldn't blend (`NbFaultyVertices`). It costs nothing more than the failed run, and names only edges OCCT says failed: OCCT's report of colliding contours names one of the pair, not necessarily one at fault, so it names nothing (`/break-it` found it). Where OCCT names none, the refusal names no edge, as before. A chamfer's edges are named the same way, through Silico's OCCT patch 0002 (the maintainer agreed it, and the read-only exception to the patch policy it needed), but not through corners, which mislead for chamfers (docs/ports/chamfer.md). `candidates` stays empty until something has fixes to offer (a broken reference's likely matches, M2.8).

### M2.1 – Schema and canonical JSON (done)

- **The design** is docs/design/m2.1-document-format.md, its eight decisions the maintainer's. A document holds primitives (each at a `position`) and booleans (`fuse`, `cut`, `common`, consuming their `base` and `tool`); fillet and chamfer join when the naming study fixes how a file names an edge, and extrude and revolve arrive with sketches.
- **The reader is Silico's own** (`document::json`): strict JSON, every number kept as its text, every value its line and column, no byte-order mark, no key twice, nesting at most 64 deep, at most 64 MiB of text read into a tree of at most about 256 MiB, counted as it's built, so any text costs about that at most to read or refuse; a document opens, and saves, only if its canonical text is at most 16 MiB (measured on canonical text by `read` and `write` alike, so what opens can be saved). Serde can't hand a number's text to a field inside an enum tagged by `type`, which a document's features are. Lengths and angles (`Length`, `Angle`: `i64` nanometres and nanodegrees) are read from the number's text, never through a float: `0.1` is exactly 100,000 nm, and an exponent is read exactly too (`1e-05` is 10 nm, as Python writes it), while a non-zero digit past the resolution, `-0`, and a value past `i64` are refused. Values are plain numbers; strings are reserved for expressions (the maintainer's choice, D4).
- **Every refusal is `invalid_input`** (no new code), naming the feature (its ID, or `features[N]` when the ID is at fault), the field (`position.2`), and the line and column. A value an error repeats is quoted, its control and invisible characters escaped, and cut short at 40 characters, so no document makes its error unreadable or unsafe to print.
- **The types hold only what the file can** (`Name` isn't empty; `FeatureVersion` is 1 until a type has more), so whatever is written reads back as itself (`/break-it` found an empty name saved as a file that wouldn't open).
- **The writer** writes canonical form from the types alone: any spelling of a document writes the same bytes.
- **The schema** (`document::schema`, generated by `schemars`, its keys sorted so the build's serde_json features can't change it) is a contract: `crates/silico-core/tests/contract/document-schema.json`. A validator checks every document the tests write against it. It gives lengths no `multipleOf`: validators divide in floating point and would refuse 0.1 mm.
- **Fuzzed:** the gate's fuzzing is the property tests (random bytes, token soup, damaged documents, and every document written read back). `crates/silico-core/fuzz` (targets `document` and `decimal`, run by hand with `cargo fuzz`, as `silico-protocol`'s are) ran 5 minutes each on 2026-10-13: 12.1 and 25.1 million runs, no crash.
- **Not yet:** the first golden documents (`tests/golden/`, protected) wait for the maintainer; the design's canonical texts in `tests/document.rs` pin the bytes until then. An error's line and column are in its message, not a field of their own, until the error contract next opens (M2.9).

### M2.2 – Validation gate (done)

- **`document::validate`** checks what a read document's features say about each other, and whether the kernel can make each: every ID names one feature; every `base` and `tool` is the ID of a feature before the one using it, so the timeline can't hold a cycle (a reference to itself or to a later feature is refused, naming the later one); a solid is consumed once (a second use is refused, naming the feature that consumed it, and so is a boolean of a solid with itself, as the design's D2 has it); and every primitive's values and position are ones the kernel accepts. The values are checked by the kernel's own rules (`Primitive::faults`, of which the kernel's `check` is the first, and `check_offset`), on the millimetres the kernel will be sent, so the gate and the kernel can't disagree; the rule names each value as the document does (a box's `length`, not the kernel's `dx`), and the gate reports every value at fault, not the first.
- **Every problem at once**, in timeline order, each an `invalid_input` error naming the feature (its ID, or `features[N]` where two features share the ID) and the field (`base`, `position.2`, `radius2`): the first hundred as errors, and how many there are in all, so a document with a problem in every feature costs no more to refuse than to read. The gate's errors carry no line and column: it checks the typed document, not its text.
- **Versions and units** are the reader's (M2.1): a feature version or a units header other than version 1's is refused as the document is read, as a value the types can't hold.

### M2.3 – Kernel trait and fake kernel (done)

- **`kernel::Kernel`** is what recompute will run requests on: a generation, `advance` to supersede older ones, and `submit` of a typed `KernelRequest` for a `Pending` outcome. The worker pool implements it as it was; nothing above the trait sees which kernel it has.
- **`fake::FakeKernel`** is the in-memory kernel for core tests. It runs requests on threads as the pool runs them on workers, with the same generations (waiting requests of an older generation dropped, held ones stopped, a result finished after its generation was superseded discarded), and records every call it starts, with its generation and operation, so a test can assert what was recomputed. A request's reply is read and checked exactly as a worker's is (`KernelRequest::answer`), so the fake can't hand recompute anything a worker couldn't.
- **Its shapes are symbolic, and their bytes say all there is to them**, as a B-rep's do: the steps that made the shape, one to a line, each operation naming its inputs by their lines (`box 40 20 10`, `cylinder 2.5 12`, `translate 1 20 10 -1`, `cut 0 2`), in one canonical order and spelling, which is all the fake reads. So any fake kernel reads a shape any other made, as any worker reads any B-rep, and a cache test can drop one kernel and go on with another; the same request makes the same bytes on any kernel, thread, or run. A primitive has OCCT's faces, edges, and vertices (a cone's caps decided by OCCT's own rule, computed as OCCT computes it, with the `libm` OCCT uses, so a radius at the edge of its tolerance falls as it does in OCCT), and a zero of either sign in its values is the same. A move reports OCCT's history (each element modified into its own number, or kept by a move of nothing), and composes as OCCT's locations do: moved twice is moved once by the sum, keeping the sign of a zero as OCCT does, and a move by nothing, or back, is the shape itself. silico-kernel's `tests/fake_kernel.rs` and `tests/adversarial_fake_kernel.rs` run the same requests on the pool and the fake and compare counts, histories, and which shapes are the same shape, over 2,000 generated primitives too. Two differences are known and pinned: OCCT refuses some tori whose tube is wider than their ring (by no more than its tolerance, which the protocol's check allows), by the floating point of its revolve, which the fake builds (a test of that refusal gives it with `refuse`); and OCCT writes a cylinder or torus differently once it has read it back, so its bytes change once, on the first operation they pass through, where the fake's never do. A boolean is the fake's own model: both inputs' elements, kept whole, the tool's numbered after the base's. It answers primitives, moves, booleans, and echoes, and refuses anything else as an internal error.
- **Only for tests**: the fake is behind silico-core's `fake` feature, which its own tests and silico-kernel's turn on, so no client links it.
- **For recompute's tests**: a test can hold requests until released (`hold`), to see what runs at once (`wait_running`, `most_running`) or supersede a request mid-run, and have requests refused with a given error (`refuse`). A rule that panics fails its request as an internal error naming it, and the kernel runs on; an outcome is decided and sent under the lock `advance` takes, as the pool's is (and with the pool's own `deliver`), so no result of an older generation arrives after `advance` returns, and a request stops counting as running only once its outcome is sent (`/break-it` and the review found these). A request runs in the tracing span it was submitted in, as on the pool.

### M2.4 – Recompute (done)

- **The study** is docs/ports/recompute.md: what FreeCAD's recompute does (sorted by links, touched bits, a failure skipping its users while they show stale shapes, no parallelism), the bug fixes from its history, and what Silico does instead. M2.4 takes each of its recommended defaults, which the maintainer reviews at M2's end.
- **`recompute::Recompute`** rebuilds a `document::Checked` (a document the gate passed, the only kind it takes) on any `Kernel`, in the background: `start` returns a `Run` at once, to wait on, poll, or drop.
- **Keys, not touched bits.** Each feature is one or two kernel steps (a primitive made at the origin, then moved, unless its position is the origin; a boolean of two features' solids), each keyed by SHA-256 of exactly what it computes (every number by its bits) and its inputs' keys; never a feature's ID, name, note, or place. All keys are known before anything runs, and a step runs only if no result is kept for its key: an unchanged, renamed, re-noted, or reordered document runs nothing; a value edit runs that feature's steps and those below; a position edit runs the move, not the make; identical steps run once.
- **Parallel.** Steps run as their inputs are built, up to 64 waited on at once, so independent branches overlap on the kernel; nothing depends on the order they finish in.
- **Failures, as SolidWorks.** A refused step fails its feature (the kernel's error, naming the feature); each feature using a failed or blocked one is blocked on the failure at the root; every other feature builds, and a failed or blocked feature consumes nothing, so its inputs stay bodies. A refusal that follows from the values (`invalid_input`, `kernel_failed`, `invalid_result`) is kept with its key and not asked again; a crash, timeout, or shortage is tried again by the next recompute.
- **Generations.** Each recompute advances the kernel's generation, superseding the one before; a recompute's `Model` (each feature's outcome, the bodies, the errors in timeline order) is published whole, only if no newer recompute started, so a superseded or cancelled one leaves the published model as it was.
- **Kept results** are bounded: those the last two published models' plans use (an undo runs nothing) and the newest recompute's (a superseded one's work isn't lost), nothing more. OCCT running out of memory, where its exception reaches Silico, is `resource_exhausted` (a new refusal, `OutOfMemory`), so it isn't kept as if the values were at fault; OCCT's booleans and fillets catch OCCT's own out-of-memory exception and report a failure, which is kept (a decision for M2's end; there's no forced rebuild yet).
- **Traced:** a step's span, naming its first feature, descends from the recompute's and the caller's, at warning level, so at the default level a warning on a step's thread says the edit, the generation, and the feature; and a worker's own log lines, which the core forwards from their own thread, go under the span their request was asked in (each worker remembers it for its request in flight), so an OCCT warning in a worker names them too. A step that panics (a bug) ends the recompute with an `internal` error naming the panic and the feature.
- **Tested** on the fake kernel (what each edit runs, call for call; failures and blocks; parallel branches and a chain; supersession and cancellation; kept results and an undo; the same model at kernel sizes 1, 2, and 8 and in any release order; a property test against a sequential evaluator) and on OCCT (the example builds, valid, to the same bytes twice).
