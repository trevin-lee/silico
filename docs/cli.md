# The `silico` command

Each command is a thin client of the core's commands (`silico_core::command`), which the app and MCP (`silico serve`) run too, so they all do the same thing: `check`, `fmt`, `show`, `cache clear`, and `export` open each file as a session, run one command on it (`check`, `format`, `outline`, `cache_clear`, `export`), and close it (docs/design/m4.1-command-api.md, section 9); `fmt --merge-touching` runs `check` and a `sketch_merge` for each cluster of touching ends before its `format`, in one transaction. `check` and `fmt` run every file on one kernel pool and one sketch solver, and `export` its file on one of each; `show` and `cache clear` rebuild nothing, so they start neither.

| Command | What it does |
|---|---|
| `silico check [--json] [--fresh] FILE...` | Reads each document, puts it through the gate, rebuilds it (solving each sketch from the coordinates its file stores), and compares each feature's stored fingerprint, and each sketch's stored points, radii, and reference values, with the rebuild: a difference is `drift`, and a sketch that doesn't solve is a problem of its own. Every problem goes on stderr, and after them each warning, marked as one (`part.silico: warning: fingerprint_missing: …`): ends of a sketch's curves closer than FreeCAD's joining distance (1e-7 mm) that aren't one point, a warning for each cluster of them (`ends_not_joined`), a sketch's redundant constraints that agree with the rest (`constraints_redundant`), and apart from them its partially redundant ones (`constraints_partially_redundant`), and a feature that built whose file stores no fingerprint (`fingerprint_missing`, which `fmt` mends), the first 100 said and the rest counted (docs/design/m4.1-command-api.md, *Warnings*). A warning never changes the exit code. A kernel fault (a worker that crashed, hung, or couldn't be had) isn't the document's: the problems found beside it go on stderr, then the fault, its suggestion the worker's own advice worded as a session's is, but with running `silico check` again as the way to try again, said once (docs/design/m4.1-command-api.md, section 6, quotes each case): advice to try the request again becomes "run `silico check` to try it again: …", a timeout says to simplify the operation or run `silico check` to try it again, and other advice is followed by "; then run `silico check` to try it again"; after a crash the request's values caused, which the worker's advice says the same request would cause again (the CLI reads the advice, not its words), the worker's own alone, since running it again can't help; and the file couldn't be checked (exit 2). With `--json`, one line per file goes on stdout instead: `{"file", "ok", "problems", "total", "warnings", "warnings_total"}`, where each problem and each warning is in the core's error contract's shape, the first 100 of each listed and the totals counting them all, as `check`'s result has them. A file that couldn't be checked gives `{"error", "file", "ok": false, "problems", "total", "warnings", "warnings_total"}`, its error in the same shape (`io_failed` for a file that couldn't be read, `invalid_input` naming the parameter `path` for a name that isn't UTF-8, or the kernel fault), beside the problems and warnings found with it, which stderr lists without `--json` (`[]` and 0 for a file that couldn't be read at all). The keys are sorted. The warnings go on stderr too, with `--json` as without it. Both lines are a contract (`crates/silico-cli/tests/contract/check-line.json`). With `--fresh` (the `check` command's `fresh`), the rebuild reads nothing of the rebuild cache: every step is built on the kernel and every sketch solved, as a forced rebuild does, and what it builds is kept in the cache, so the next check takes it from there; anything else, the lines and the exit codes, is as without it. |
| `silico fmt [--check] [--merge-touching] FILE...` | Rewrites each document in canonical form with its fingerprints as rebuilt and its sketches as solved (points, circles' radii, and reference dimensions' values), and says which fingerprints and which sketches' solves it wrote. Canonical form includes the header's `naming` (the naming scheme, M4.0), so `fmt` adds it to a document saved before it; `check` doesn't ask for canonical form, so it finds nothing wrong with such a document, and `fmt --check` says `fmt` would rewrite it. With `--check`, writes nothing and says whether it would. A feature that didn't build keeps the fingerprint stored with it, and a sketch that didn't solve keeps what its file holds; each says why, and the file is still written (exit 1). It accepts every feature's drift (the `format` command with no features named). A kernel fault (a worker that crashed, hung, or couldn't be had) is saved around, as a failed feature is: each feature it stopped keeps what's stored with it, the rest is written, and the fault is said last, its suggestion worded as for `check`, with "run `silico fmt` to try it again" (exit 2), as the `format` command saves around one (decision 32). So with no kernel to be had at all, `fmt` still writes the file in canonical form, every fingerprint and sketch as stored. It never writes a file this user may not write (as the system says), one whose save would pass the 16 MiB a document may be (the fingerprints and solved sketches it writes count: exit 1, saying so; exit 2 if the rebuild met a kernel fault too, said after it), or one that changed while it was being rebuilt (`conflict`, exit 2). It writes through a symbolic link to the file it names, and keeps the file's permissions. A file with other names (hard links) is written in place, its old text kept beside it (`.NAME.fmt-PID`, the name cut short if the document's is near the 255 bytes a name may be) until the new is on disk: if `fmt` is killed mid-write, that file holds the document as it was. The file is grown to its new length before it's written, so a limit on a file's size stops the write before it changes. That copy needs the directory to be writable, as a rename does: a hard-linked file in a directory this user can't write isn't formatted. With `--merge-touching` (docs/design/m5.0-app.md, `sketch_merge`, decision 17), it first makes the ends of each cluster `check` warns of as `ends_not_joined` one point, a `sketch_merge` of the cluster's points keeping its least ID, so the same file is written on every machine; all in one transaction with the rewrite, so the file is written once. Each merge is said on stderr (`part.silico: merged points pa000004, pa000007 of sketch s0000001, keeping pa000004`). A cluster whose merge is refused (a constraint it would make name one point twice, a solve it would make worse) is said, `couldn't merge points ...`, with why, and the others still merge and the file is written (exit 1). With `--check` too, it says each merge it would make, and that `fmt` would rewrite the file, and writes nothing. |
| `silico cache clear FILE...` | Removes every entry of the rebuild cache beside each file (`.silico-cache/`, the `cache_clear` command): the directory's, shared by every document in it, so two files in one directory clear one cache, the second finding nothing. Only entries go: never the cache's `.gitignore`, its subdirectories, a write's partial file, any other file in it, or anything through a link (a cache directory that's a link clears nothing). Another process rebuilding meanwhile reads each entry whole or not at all: an entry removed is only a miss, made again by the next rebuild. Says on stderr how many it removed, and from where (`part.silico: removed 214 entries from .silico-cache`). Needs no kernel and doesn't read the cache's secret. An entry it couldn't remove, or a directory of the cache it couldn't read, is said (`io_failed`), the rest removed, and the command couldn't run (exit 2). |
| `silico show FILE` | The document's outline (the `outline` command): one line per feature, with its values and fingerprint (`suppressed` before its type, for a suppressed one), then its note, for a sketch its points, curves, and constraints, a line each as the file writes them, and for a fillet or chamfer its edges, a line each; then the bodies. Needs no kernel. |
| `silico export [--tolerance=MM] [--features=ID,...] [--replace] FILE OUT.3mf`, `silico export [--features=ID,...] [--replace] FILE OUT.step\|OUT.stp` | The format is the output's: `.3mf`, or `.step` or `.stp` (STEP's two spellings, written alike). A STEP file holds each body's exact shape, each a product named by its feature, its header written from the document so its bytes are the same every run (docs/ports/step-export.md); it takes no tolerance, so `--tolerance` with `.step` is a usage error, and each object's line is its feature's ID and name alone. Any other extension is a usage error (exit 2). For 3MF: writes the document's bodies (or the features `--features` names, in that order) as a printable 3MF file at `OUT.3mf`, each solid meshed at `--tolerance` mm (FreeCAD's 0.1 if none is given), as the `export` command writes it (docs/design/m4.1-command-api.md, `export`; docs/ports/mesh-export.md): closed, manifold, oriented outward, and within the tolerance, one object a body named by its feature, the archive's bytes the same every run. On stdout, where it went and its size, then a line per object: its feature's ID and name, its triangles and vertices, its mesh's volume, and any faces left out as bounding no material. It reads the document's current revision, rebuilt. Refused, with every reason on stderr and nothing written (exit 1): a file already at `OUT.3mf` without `--replace`, a document's path, a tolerance out of range, a feature listed twice, or that the document hasn't or that makes no solid (its own failure, as `check` says it), a feature name a 3MF file can't hold, and a solid that isn't printable at the tolerance (naming its feature and the faces at fault). Without `--features`, a document some of whose features didn't build is refused too, each failure said after: a failed feature consumes nothing, so its bodies aren't the ones the document describes; name the features to export instead (if a kernel fault alone stopped them, only the fault is said). A kernel fault (a worker that crashed, hung, or couldn't be had) is said once, its suggestion worded as for `check`, with "run `silico export` to try it again" (exit 2): where the refusal lists it (a feature it stopped), there; otherwise last, after the refusal, or after a file written of features it didn't stop. A tolerance or a feature's ID that isn't one, or a missing path, is a usage error (exit 2). |
| `silico schema [NAME]` | The document's JSON Schema, exactly as `crates/silico-core/tests/contract/document-schema.json` holds it; or, given a command's name (`version`, `open`, `status`, `cancel`, `begin`, `add_feature`, `text`, `check`, `elements`, `query`, `schema`, `mass_properties`, ...), its request's and its result's schemas, `{"request", "result"}`, as its snapshot in `tests/contract/commands/` holds them, so a script reads the shapes of a call's arguments and of its result. Needs no kernel and no file. A name that's neither is exit 2, with the names it takes. |
| `silico textconv FILE` | Git's text conversion: the outline, if the file reads as a document; otherwise the file as it is (conflict markers, a half-made edit), so `git diff` still shows it. |
| `silico serve [--workspace DIR]` | The MCP server (docs/design/m4.9-mcp.md; connecting an agent to it: docs/mcp.md): MCP 2025-06-18, JSON-RPC 2.0 one message a line, on stdin and stdout, for one client, as an MCP client starts it; every command is a tool (`tools/list`), its answer the command's envelope exactly. Its documents are in the workspace, `DIR` or the current directory: every path a tool takes is relative to it, and none may lead out of it. The root of a disk (`/`) is refused as the workspace (exit 2), since some MCP clients start servers there. It starts one kernel pool, sketch solver, and render worker, and looks for the STEP worker, each found as **Workers** below says. It starts with all four or not at all: if any isn't there (or can't be read), it says on stderr which, each where it looked, in one message, and exits 2 before the handshake, since a missing worker is a broken install that an agent would otherwise meet only at the command that needs it. Nothing but MCP's messages goes on stdout; logs go to stderr (`SILICO_LOG`, as for every command). It runs until stdin ends, stdout closes, or SIGTERM, then cancels every call in flight and rolls back every open transaction (exit 0), an answer being written as stdin ends written whole first; a second SIGTERM while it ends exits at once (exit 1); stdin that can't be read is exit 2. `--workspace=DIR` is the same as `--workspace DIR`. |

`--` ends the options, so a file can be named like one; `cache`'s `clear` comes before the files, and before `--` or after it. `check`, `fmt`, `show`, and `cache clear` refuse a file whose name isn't UTF-8 as a file that couldn't be read (exit 2), as the session commands every client runs refuse it, since a response couldn't name it exactly: the refusal names the parameter `path`; `textconv` reads it. A file's name is shown as it is, unless it holds a character a terminal would act on or draw as nothing (a control, an invisible character, a space but the plain one), a quote, or a backslash: then it's shown quoted, with those escaped as an outline escapes a document's text (`"bad\u{1b}.silico"`). A JSON line holds the name itself.

**Workers.** `silico` runs OCCT, PlaneGCS, and the renderer in worker processes (`silico-kernel-worker`, `silico-sketch-worker`, `silico-render-worker`, `silico-step-worker`), each found in the directory of `silico`'s own executable, its links resolved: a link to the build's `silico` (on `PATH`, say) finds the workers beside the build. `SILICO_KERNEL_WORKER`, `SILICO_SKETCH_WORKER`, `SILICO_RENDER_WORKER`, and `SILICO_STEP_WORKER` name one elsewhere. A worker that isn't there is `worker_unavailable`, naming the directory looked in and the worker looked for (exit 2).

**Exit codes:**
- 0: nothing wrong.
- 1: a document has problems, or (with `fmt --check`) isn't in canonical form, or a file is longer than a document may be.
- 2: the command couldn't run. That means a usage error, a file that couldn't be read or written, or whose name isn't UTF-8, a cache entry `cache clear` couldn't remove, a file that changed while `fmt` rebuilt it (run `silico fmt` again), or a kernel or sketch solver that couldn't start or failed for reasons that aren't the document's (a worker crashed or hung, or something ran short).

## `git diff` of a document

To diff the outline rather than the JSON, add this to the repository's `.gitattributes`:

```
*.silico diff=silico
```

and tell git how to convert (once per clone, or in your global config):

```bash
git config diff.silico.textconv "silico textconv"
```

An edit to one value then diffs as one line of the outline, and each feature's line stays the same unless that feature changes.
